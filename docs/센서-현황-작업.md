# 센서 현황 작업 (피드백 반영)

센서 현황(대문 `/`) 화면에 받은 피드백과 그 작업 목록이다. 작업하면서 체크한다.
관련 문서: `docs/대문-평면도-대시보드-계획.md`(처음 계획), `docs/웹-DB-화면역할.md`(화면 동작).

## 받은 피드백 (2026-11-23)

- 좌측 상단 알림을 초음파/진동으로 구분
  - 총 몇 개 센서 중 몇 개가 이상인지 표시
  - 진동과 초음파 각각 이상 신호의 용어 정리와 단계 구분(예: 초음파 = 누출, 진동 = 진동 이상, 단계 2개)
- 우측 센서 목록을 숨길 수 있게
  - 센서 목록의 '대기'가 무엇인지 궁금해함
- 평면도 아이콘을 누르면 팝업에 사진 포함
  - 사진 + 정보
  - MEMS/PIEZO 대신 Type1, Type2처럼 쉬운 이름
  - 아이콘의 이상 표시(예: 끊김 = 느낌표)를 센서 목록에도 똑같이
- 센서 '자세히 보기' → 통계가 아니라 분석 화면으로
  - 그 센서 MAC 선택과 조회가 자동으로 되어 분석 그래프까지

## 진행 기록

### 2026-11-23 — 1번, 2번 완료

**1. 자세히 보기 → 분석 화면 자동 조회**

- 팝업 아래 링크: **'자세히 보기 →'**(주 버튼, 센서 데이터 분석) + '통계 보기'(그대로 둠).
- 누르면 `/studio`로 가서 자동으로: 센서 종류 탭 고르기(MEMS / PIEZO / 초음파) → MAC 선택 → 조회 → 그래프.
- 주소에 MAC을 남기지 않는다. `sessionStorage('studio-focus')`에 `{mac, kind}`를 넣고 분석 화면이 한 번 읽고 지운다(새로고침하면 다시 열지 않음). 통계 화면 강조와 같은 방식.
- 수신 기록이 없는 MAC(설정만 있는 장치)은 "저장된 수신 기록이 없어 열 수 없습니다"를 보여 준다.
- 파일: `static/site.js`(팝업 링크), `static/db.js`(자동 조회), `static/site.css`.

**2. 센서 목록 숨기기**

- 위쪽 오른쪽 **☰** 버튼(누를 때마다 숨김/보임), 목록 머리의 **»** 버튼(숨김).
- 숨기면 평면도가 화면 폭을 다 쓴다(1600 px 화면에서 평면도 1247 → 1557 px). 확대 중이면 범위를 다시 맞춘다.
- 숨김 상태는 브라우저에 기억한다(`localStorage 'site-list-hidden'`). 설정 '평면도 배치'에는 없다(배치할 때는 목록이 필요).
- 파일: `site.html`, `static/site.js`, `static/site.css`.

**확인**

- 브라우저 자동 조작: MEMS(165874312270)와 초음파(2A596F383F70) 각각 팝업 → 자세히 보기 → 탭·MAC 선택·조회까지 자동(50세트 열림), 넘긴 값은 지워짐. 목록 숨김·새로고침 뒤 유지·다시 보이기·» 버튼 모두 정상.
- HTTP 점검 119/119.


### 2026-11-23 — 3·4·5·6번 완료

**3. 위쪽 요약**

- 진동(Type1·Type2) / 초음파(Type3) 두 카드. 카드마다 `총 N개`(카드 머리에는 '진동'·'초음파'만, Type 글자 없음 — 2026-11-24), `상태 [경보 n] [위험 n]`, `수신 [정상 n] [이상 n] [확인 불가 n]`.
- 수신 '이상' = 지연 + 미수신. 서버가 센서마다 `link_group`(ok / bad / unknown)을 같이 준다.
- 기준이 없는 Type1·Type3은 상태 줄에 '기준 없음(표시만)'.
- 칩을 누르면 그 묶음·상태만 강조하고 목록도 거른다(예: `vib:alarm`). 다시 누르면 풀린다.

**4. 이름**

- 끊김 → **미수신**, 대기 → **확인 불가**. 단계 이름: 주의 → **경보**(80% 이상), 경보 → **위험**(한계 이상). 수신 지연은 따로 **지연**(노랑).
- 상태 순서: 위험 > 미수신 > 경보 > 지연 > 정상 > 확인 불가. 확인 불가 이유(수신 꺼짐·측정 중지·데이터 없음 등)는 목록 둘째 줄과 카드에 그대로 보인다.
- 최근 알림 '확인 안 한 것'에 지연도 센다.

**5. 종류 이름**: Type1 = PIEZO 진동, Type2 = MEMS 진동, Type3 = 초음파. 목록·카드·범례·요약에 쓴다.

**6. 아이콘**

- `iconHtml()` 하나를 평면도 아이콘·목록·정보 카드가 같이 쓴다: 색 = 상태, 안 그림 = 종류, 오른쪽 위 빨간 '!' = 배터리 부족(3 이하).
- 목록 오른쪽: 상태 글씨 알약 + 배터리. 범례: 상태 6개, '! 배터리 부족', 종류 그림 3개.
- 파일: `src/site_status.py`, `src/store_site.py`, `static/site.js`, `static/site.css`, `site.html`.

**확인**: 브라우저 자동 조작으로 요약·칩 거르기(위험 → 2개만 남고 5개 흐림)·목록 아이콘·범례·카드 확인. HTTP 점검 119/119.

### 2026-11-23 — 진동 네 구간(양호 / 주의 / 경고 / 위험)

요청: ISO 20816-3 Group 2(강성 지지) 평가 구간 그림대로. A 양호 < 1.4 → **양호**, B 허용 1.4~2.8 → **주의**, C 개선 2.8~4.5 → **경고**, D 위험 ≥ 4.5 → **위험** (mm/s RMS, 최근 한 시간 통계 SRSS).

- 경계는 MAC마다 세 값(양호 상한·주의 상한·위험 기준). 위험 기준 = 예전 SRSS 한계. 양호·주의 상한이 비어 있으면 위험 기준의 ISO 비율(× 1.4/4.5, × 2.8/4.5)로 자동. 한계가 14·15인 MAC도 비율이 맞게 나뉜다(15 → 4.67 / 9.33).
- 상태 여덟 가지(나쁜 것부터): 위험 > 미수신 > 경고 > 지연 > 주의 > 양호 > 정상 > 확인 불가. '정상'은 판정 기준이 없는 Type1·Type3(또는 통계 전 MEMS)이 제때 수신 중일 때. 주의·양호는 제때 수신 중일 때만 보인다.
- 색: 양호 초록, 주의 올리브(지연 노랑과 구분), 경고 주황, 위험 빨강, 정상 청록.
- 위쪽 요약 상태 칩: 양호 · 주의 · 경고 · 위험. 정보 카드 안내: '진동 주의 · 1.4 mm/s 이상'처럼 그 MAC 경계값.
- 상태 기록: 정상 ↔ 양호는 기록하지 않는다(도입 직후 모든 MEMS가 한꺼번에 바뀌는 것 방지). 주의는 기록하되 '최근 알림' 숫자에 세지 않는다.
- 설정 > 장치 표: 'SRSS 한계' 칸 → '양호 상한 · 주의 상한 · 위험 기준' 세 칸(비우면 자동, 흐린 글자가 자동값). 통계 화면 막대도 네 구간 색과 경계 점선.
- 파일: `src/limits.py`(zone_bounds, zone_of), `src/site_status.py`, `src/store.py`(srss_limit 열, get_zones·save_zones), `src/store_site.py`, `src/store_query.py`, `src/routes/db.py`(`POST /api/db/zones`), `static/site.js`, `static/site.css`, `static/settings.js`, `settings.html`, `dashboard.html`.

**확인**: HTTP 점검 136/136(구간 경계 1.39/1.4/2.8/4.49/4.5, 상태 줄이기, 구간 저장 거부·자동, 정상→양호 무기록). 브라우저: 센서 현황 요약 '양호 5 · 주의 2 · 경고 0 · 위험 0'과 범례 8개, 설정 표 세 칸 저장·순서 오류 안내, 통계 화면 구간 색(통계 없는 MAC '-').

### 2026-11-24 — 재송신하면 받자마자 '미수신'이 되던 문제

증상: 데이터 분석 CSV로 옛 데이터를 몰아서 보내면 수신은 되는데(마지막 수신 시각은 바뀜) 센서 현황이 곧바로 '미수신'으로 바뀌었다.

- 원인: 원래 간격을 '최근 수신 간격의 중앙값'만으로 정했다. 몰아 보낸 세트 간격이 2.56초(초음파는 1초)라 간격이 2.56초가 되고, 정상 기준(간격 + 30초)을 33초 만에 넘었다. 8060 서버 15:44 기준 13대 중 9대가 이 때문에 미수신이었다.
- 고침(`site_status.expected_interval`): 원래 간격 = max(실제 간격 중앙값, 설정 SENSING_PERIOD), 최소 60초(`MIN_INTERVAL_S`). 실제 간격이 설정보다 길면(센서가 늦게 보냄) 실제 간격을 쓴다.
- 고침(`site_status.measure_times`): 초음파는 측정 한 번에 패킷 3~4개를 약 1초 간격으로 보낸다. 앞 패킷과 2초(`SAME_MEASURE_S`) 안이면 같은 측정으로 센다(예전에는 패킷마다 측정으로 세어 간격이 1초).

**확인**: 같은 원자료로 다시 판정하면 미수신 9 → 1(D25871312270, 11-19 뒤로 실제로 수신 없음). 함수 시험 7/7(재송신 몰아치기 + 설정 3600 → 3600초, 실제가 더 길면 실제, 짧은 주기 하한 60초, 초음파 4패킷 = 측정 한 번, 2시간 넘게 없으면 미수신). HTTP 점검 146/149(나머지 3개는 실제 DB 차이).
