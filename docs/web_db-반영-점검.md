## A. 결정이 필요한 것

### A-1. escape 바이트가 든 PIEZO가 분석 화면에서 깨짐

**escape란.** 센서는 무선으로 보낼 때 `7E`를 프레임 경계 표시로 쓴다. 그래서 데이터 안에 `7E`나 `7D` 바이트가 나오면 두 바이트로 바꿔 보낸다(byte stuffing). 받는 쪽이 되돌려야 원래 값이 된다.

```text
원래 데이터 :  7E          7D
보내는 HEX  :  7D 5E       7D 5D      (한 바이트가 두 바이트로 늘어남)
```

PIEZO는 이 규칙을 쓴다(수신기 V057 `decode_piezo_samples`가 되돌림). ADXL은 되돌리지 않는 규칙이다(V016 시험부터). 그래서 이 문제는 PIEZO만 해당한다.

**웹에서 무슨 일이 생기나.** 저장되는 HEX는 받은 그대로, 즉 **escape된 상태**다(CSV `sensorData_hex`, DB `sensor_data_hex`). 이 HEX를 화면마다 다르게 읽는다.

| 화면 | 읽는 함수 | escape 되돌림 |
| --- | --- | --- |
| 센서 수신 모니터 | `decode_piezo_samples` | O |
| DB `decoded_samples` | 수신 때 위 함수 결과 | O |
| 데이터 분석 CSV `/generator`, 센서 데이터 분석 `/studio`, FFT 검증, PSD | `graph_options.decode_wave` | **X** |

예: 샘플 하나가 `7E 01`(32257)인 패킷

```text
보낸 HEX       :  ... 7D 5E 01 ...
수신 모니터    :  7E 01 → 32257             (정상)
분석 화면      :  7D 5E | 01 ?? | ...       (한 바이트가 남아 그 뒤가 모두 밀림)
```

- escape가 홀수 번이면 바이트 수가 홀수라 `PIEZO bytes 길이는 짝수여야 합니다` 오류로 그래프가 안 뜬다(시험에서 확인).
- escape가 짝수 번이면 그래프는 뜨지만, 첫 escape 뒤 샘플이 모두 엉뚱한 값이 된다. 오류가 안 나서 알아채기 더 어렵다.
- 재전송은 원본 HEX를 그대로 보내므로 받는 수신기는 정상이다. **분석 화면의 그래프만** 문제다.

**왜 이렇게 됐나.** 발생기 v070의 `decode_packet`도 escape를 되돌리지 않는다. 웹은 v070을 그대로 옮겼다. 그래서 "v070과 같다"는 맞지만, 웹 안에서 수신 모니터와 분석 화면이 같은 패킷을 다르게 그린다. v070에도 있는 문제다.

**얼마나 자주 생기나.** 데이터에 따라 다르다. 실제 수신 CSV의 PIEZO `sensorData_hex` 열에서 `7D5E`나 `7D5D`를 검색하면 바로 알 수 있다. 하나도 없으면 지금 데이터에서는 문제가 없다.

**선택지**
1. `decode_wave`에서 PIEZO일 때 `decode_piezo_samples`(escape 되돌림)를 쓴다. 수신 모니터와 같은 값이 되고, v070과는 달라진다(v070의 버그를 고치는 쪽).
2. v070과 똑같이 둔다.

## D. 웹에 없는 데스크톱 기능

기능마다 **프로그램이 실제로 하는 일**, **웹 지금**, **넣을 때 작업**을 적었다. 작업량은 대략 소(반나절 안) / 중(하루 안팎) / 대(며칠). 번호는 11-20 점검 때의 번호를 그대로 쓴다(D-1~D-4, D-9는 반영함).

### D-5. 시리얼(COM) 수신 — 작업량 대

- 프로그램: MQTT 대신 COM 포트·Baud를 골라 연결한다. 시리얼 스트림에서 JSON 객체를 잘라 MQTT와 같은 처리로 넘긴다. 센서가 `{"CONFIG":"READY"}`를 보내면 지금 화면의 설정 JSON을 자동으로 한 번 보낸다(끝에 CR). 센서를 PC에 직접 꽂아 설정·시험할 때 쓴다.
- 웹: 없음.
- 넣을 때: 서버(Docker 컨테이너)가 USB 장치에 접근해야 한다(`--device`, 권한). 브라우저 PC가 아니라 **서버 PC**에 꽂아야 한다. 운영 서버 용도와 맞지 않아 필요성이 낮다.

### D-6. PIEZO 실측 교정(`counts_per_g`) — 작업량 중, 넣을 필요 낮음

- 프로그램: PIEZO 그래프 창에 '시험기 기준 진동 (RMS) [g]' 칸과 '현재 패킷 기준으로 보정', '보정 해제' 버튼이 있다. 누르면 `counts_per_g = 지금 패킷 AC RMS(Count) / 기준 g RMS`를 장치·축별로 메모리에 둔다. 파일에 저장하지 않아 프로그램을 끄면 사라진다.
- 확인한 것: 이 값은 단위가 `"g"`일 때만 그래프에 쓰이는데, V057 단위 목록에는 `"g"` 항목이 없다(전압 / Count / 가속도 g(감도 100 mV/g) / 속도). 그래서 **V057에서도 버튼은 있지만 그래프에 반영되지 않는 상태**다.
- 웹: 없음. 웹은 감도(mV/g) 칸으로 g를 낸다(V057의 `g_spec`과 같음).

### D-7. PIEZO 장치별 Vmax 저장 — 작업량 소~중

- 프로그램: PIEZO 그래프 창의 Vmax 칸 값을 `piezo_device_voltages.json`(`{"장치 MAC": 볼트}`)에 장치별로 저장한다. 장치를 바꾸면 그 장치의 Vmax로 칸이 바뀌고, 칸을 고치면 바로 저장한다. 없으면 3.89 V.
- 웹: Vmax 칸은 있지만 장치와 상관없이 하나다(서버 메모리 옵션, 저장 안 됨).
- 넣을 때: SRSS 한계처럼 장치별로 저장(DB 표 또는 JSON 파일), 수신 모니터·분석 화면이 장치를 바꿀 때 읽기. 센서마다 기준 전압이 다르면 쓸모가 있다.

### D-8. RAW Y 대칭로그(SymLog) — 작업량 중

- 프로그램: RAW 그래프 Y축을 대칭 로그로 바꾸는 체크. 0 근처는 그대로, 큰 값은 로그로 눌러서, 큰 충격과 작은 진동을 한 화면에서 같이 본다. 음수도 유지한다.
- 웹: 없음. Chart.js에 대칭 로그 축이 없어 값을 변환해 그리고 눈금 글자를 되돌려 써야 한다. 고정 커서 값 상자도 변환 전 값으로 보여 주게 맞춰야 한다.

### D-10. 그래프 이미지 저장 — 작업량 소

- 프로그램(발생기 v070): '미리보기 그래프 저장'으로 RAW+FFT 그림을 PNG·PDF·SVG로 저장(160 dpi).
- 웹: 없음. 브라우저 화면 캡처로 대신한다.
- 넣을 때: Chart.js `toBase64Image()`로 PNG 내려받기 버튼. RAW와 FFT를 따로 또는 합쳐 저장할지 정해야 한다. PDF·SVG는 따로 작업이 든다.

### D-11. MQTT User / Password — 작업량 소, 이력 확인 필요

- 프로그램: 발생기 v070 브로커 칸에 User·Password(가림 표시)가 있고, 값이 있으면 `username_pw_set`으로 접속한다. 수신기 V057에는 없다.
- 웹: 수신·송신 모두 계정 없이 접속.
- 참고: 커밋 `7d4b875 "user, password 부분으로 인해 동작하지 못하는 기능들 수정"`에서 문제가 있었다. 넣는다면 빈 값이면 아예 호출하지 않게 하고, 비밀번호를 DB·로그에 남기지 않아야 한다.

### D-12. 수신 화면 회전 부품 역추정 — 작업량 소~중

- 프로그램: 수신 그래프 창에 RPM을 넣고 실행하면, 지금 FFT 봉우리가 회전 주파수의 몇 배(부품 개수 2~48)와 맞는지 점수로 후보 5개를 보여 주고 FFT에 표시선을 그린다. 장치를 바꾸면 결과를 지운다.
- 웹: 같은 계산(`rotating_candidates`)이 분석 화면에는 있다. 수신 모니터에만 없다.
- 넣을 때: 이미 있는 함수를 `monitor_curves` 결과에 붙이고 화면에 RPM 칸·결과 칸.

### D-13. SciPy 비교 그래프 — 작업량 중, 필요성 낮음

- 프로그램: 별도 창에서 같은 패킷을 SciPy(`scipy.signal` 필터, `scipy.fft`)로 계산한 결과와 자체 계산을 겹쳐 그린다. 계산이 맞는지 검증하는 개발용 기능이다.
- 웹: 없음. Docker 이미지에 SciPy가 없다(`web_db/requirements.txt`, 전 이름 `requirements-web.txt`).

### D-14. ADXL CSV를 X/Y/Z 세트가 모인 뒤 기록 — 작업량 중, 선택 필요

- 프로그램: ADXL 축 패킷을 바로 쓰지 않고 장치별로 모은다. X → Y → Z가 순서대로, 서로 맞게(샘플링·개수 등) 다 왔을 때만 세 줄을 함께 쓴다.
  - `X, X, X, Y, Z` → 앞의 X 두 개 버림, 마지막 X+Y+Z만 저장
  - `X, Y, X` → 첫 X/Y 버림, 마지막 X부터 새 세트
  - Y나 Z가 먼저 오면 저장 안 함
  - 그래서 세 축 파일의 행 수와 packet_no가 늘 같다.
- 웹: 축이 오는 즉시 쓰고, packet_no는 세트 번호(seq 규칙)로 매긴다. 축이 빠진 세트도 남는다. 열 때(`load_adxl_csv_xyz`)와 CSV 통계는 완전한 세트만 쓴다.
- 고를 점: 프로그램 방식은 CSV가 깔끔하지만 **빠진 축이 있는 측정은 CSV에서 사라진다**. 웹 방식은 원본을 다 남긴다. DB `packet`은 어느 쪽이든 다 남는다. CSV를 원본 보관용으로 쓰는 지금 구조(CSV 일자별 통계)에서는 웹 방식이 안전하다.

### D-15. 디코드 실패 패킷 HEX 기록 — 작업량 소

- 프로그램: CSV 기록 스레드가 HEX 줄을 **먼저 쓰고** 디코드한다. 디코드에 실패하면 HEX CSV에는 줄이 남고 decoded CSV에는 없다. 나중에 깨진 패킷을 다시 볼 수 있다.
- 웹: 디코드에 실패하면 CSV·DB 어디에도 남기지 않는다(로그 한 줄만).
- 넣을 때: 수신에서 디코드 실패 때도 HEX CSV에만 한 줄 쓰기(DB에는 안 넣음). CSV 일자별 통계·CSV 열기는 이미 깨진 HEX 줄을 제외하거나 앞부분만 복구한다. ADXL 세트 번호(packet_no)를 실패한 축에도 매길지 정해야 한다.

### D-16. 송신 때 빈 `acqStatus`/`apSsid`/`apRssi`를 채우기 — 작업량 소

- 프로그램(v070 `with_replay_metadata`): 보낼 패킷에 세 값이 없거나 비어 있으면 `acqStatus = "OK"`, `apSsid = "REPLAY"`, `apRssi = 0`을 넣는다. 있는 값은 그대로 둔다. 송신 시작 때 로그로 알린다. 받는 쪽에서 재생 데이터임을 알아보게 하는 용도다.
- 웹: 채우지 않는다. CSV에 값이 있으면 그 값은 그대로 보낸다(11-20 반영).
- 넣을 때: `ReplayService._publish`에 함수 하나. DB(`/studio`)에서 보내는 패킷은 세 값이 없으므로 항상 `OK/REPLAY/0`이 붙게 된다(A-2 "상태 메타데이터와 DB"와 같이 정하면 좋다).
