# 웹 시스템 기능 상세

2026-11-20 기준. 웹 = `web_db`(FastAPI + SQLite). 데스크톱 수신기(V057)·발생기(v070)를 화면 여섯 개로 옮기고, 데스크톱에 없는 센서 현황·통계·설정을 더했다.
브라우저는 화면과 그래프 조작만 하고, MQTT·HEX 디코드·FFT·CSV·DB는 서버의 파이썬이 한다. 데스크톱 `.py`를 import하지 않는다.

## 데이터는 어디서 오나 (CSV / DB / 메모리 / 파일)

작업하면서 "지금 보는 값이 CSV인지 DB인지" 헷갈리지 않게 기능마다 정리했다. **읽기** = 화면에 보여 주는 값의 출처, **쓰기** = 그 기능이 남기는 곳.

| 화면 · 기능 | 읽기 | 쓰기 | 비고 |
| --- | --- | --- | --- |
| 수신 모니터 그래프·MAC 목록 | **메모리**(지금 연결 뒤 받은 최신 패킷) | - | 서버를 다시 켜면 비어 있다. DB·CSV를 읽지 않는다 |
| 수신(패킷 들어올 때마다) | MQTT | **DB** `packet`·`device`(항상), **CSV** `data_csv_web/날짜_시각/`(수신 모니터 'CSV 저장'을 켰을 때, 기본 켜짐) | 연결은 수신 모니터에서만. 서버가 다시 켜지면 마지막 연결(CSV 체크 포함)로 다시 연결 |
| 수신 모니터 MAC 이름 | **DB** `device.display_name` | DB(이름 저장) | |
| 센서 명령(START/STOP/설정/조회) | 화면 값 | MQTT `S/{MAC}` → 보낸 설정과 되돌아온 설정을 **DB** `sensor_config` | STOP은 3단계 끝에 남는 normal 설정을 저장(`STOP → normal`) |
| 데이터 분석 CSV | **올린 파일**(임시 파일로 읽고 바로 지움) → 메모리 | - | DB 안 씀 |
| 센서 데이터 분석 | **DB** `packet`(MAC, 최근 N세트·기간) → 메모리 | - | 위 줄 '측정 n / SRSS 평균'은 DB `measurement` |
| 두 분석 화면의 전송(발생기) | 메모리(열어 둔 패킷) | MQTT | 같은 서버가 수신 중이면 다시 DB·CSV에 저장된다 |
| 속도 RMS 시간 이력 | 메모리(열어 둔 CSV 또는 DB 세트) | - | 가로축: CSV는 received_at, DB는 수신 시각 |
| 통계 화면 | **DB** `measurement` | - | 계산은 아래 두 가지가 한다 |
| 하루 통계(자정 뒤 자동) | **DB** `packet` | DB `measurement`, `stat_cursor` | |
| CSV로 일자별 통계(설정) | **CSV** `data_csv_web` 아래 전부 | DB `measurement`(전부 바꿈), `stat_cursor`, `device` | CSV가 원본 전체라는 전제 |
| 센서 현황 상태·목록 | **DB** `device`, `packet`(최근 수신 시각), `measurement`(최근 한 줄), `sensor_config`, `site_state` | - | 수신 연결 여부만 메모리 |
| 상태 기록(1분마다) | DB(위와 같음) | **DB** `site_state`, `site_state_history` | 수신 중일 때만 |
| 최근 알림 확인 | DB `site_state_history` | DB `acked_at` | 지우지 않고 숨김 |
| 평면도·배치 | **DB** `floor_plan`, `sensor_placement` + **파일** `site_files/` | 같은 곳 | |
| SRSS 한계 | **DB** `srss_limit` | DB | 설정 화면·그래프 한계선·대문 경보가 같은 값 |
| 1 LSB(g), MEMS 주파수·감도 보정 | **파일** `mems_lsb_scale.json`, `mems_frequency_sensitivity.json` | 같은 파일 | 이 PC: 저장소 루트, Docker: `/data` |
| 마지막 수신 연결 값 | **DB** `app_setting` 'mqtt' | DB(수신 모니터 연결·해제 때) | 서버 재시작 때 다시 연결에 씀. 주소·Topic·구독 QoS·CSV 체크 |
| 화면 테마, 고른 평면도 탭 | **브라우저**(localStorage) | 브라우저 | 사람마다 다름 |

### 메모리에만 있는 것(서버 전체가 하나를 같이 씀)

아래는 DB가 아니라 서버 메모리에 **하나만** 있다. 여러 사람이 동시에 쓰면 서로 덮는다(2026-11-19 점검에서 확인, 아직 고치지 않음).

| 무엇 | 영향 |
| --- | --- |
| 수신 모니터 그래프 옵션(단위·필터·창 등) | A가 바꾸면 B의 수신 모니터 그래프도 바뀐다 |
| 분석 화면에 열어 둔 패킷(센서마다 목록 하나) | A가 `/studio`에서 DB를 열면 B가 `/generator`에 올린 같은 센서 파일 목록이 바뀐다 |
| 분석 화면 그래프 옵션, 현재 패킷 위치 | 위와 같다 |
| 발생기 전송 설정·상태 | 전송은 서버에 하나만 돈다 |

혼자 쓰거나 화면별로 담당이 나뉘면 문제가 없다. 여러 사람이 동시에 분석하려면 사용자(브라우저)별로 상태를 나눠야 한다(`docs/기능-분리-구조-제안.md`와 같이 다룬다).

## 패킷과 디코드

`seq` 상위 nibble이 종류다. 0 PIEZO, 1 ADXL X, 2 ADXL Y, 3 ADXL Z. 하위 nibble은 0~F 순환(축마다 하나씩 올라간다).

- PIEZO는 `7D 5E → 7E`, `7D 5D → 7D`를 푼 뒤 4글자마다 signed int16 big-endian (`decode_piezo_samples`).
- ADXL은 escape를 풀지 않는다 (`decode_vibration_samples`). `samplerate`는 Hz와 코드(`0x08`~`0x0F`)를 모두 Hz로 읽는다 (`normalize_sample_rate`).
- 초음파 H는 12바이트 헤더 + float32 little-endian 320개 = 1292바이트 스펙트럼 (`decode_ultrasonic_samples`).

분류 순서 (`monitor_service._remember`, 2026-11-19 수정)

1. `S/`로 시작하는 토픽은 센서 설정이다. `SENSORTYPE`가 있으면 `sensor_config`에 남기고, `{"CONFIG":"?"}`(조회 요청)는 버린다.
2. **초음파를 먼저** 본다 (`classify_ultrasonic`): 토픽이 `D/`로 시작하거나, `ultrasonic`·`/ultra`가 들어 있거나, samplerate와 numofsample이 둘 다 비어 있으면 초음파.
3. 아니면 진동 (`classify_vibration`): samplerate **값**과 numofsample이 있어야 하고, seq 상위 nibble로 PIEZO/ADXL 축을 정한다.

전에는 진동을 먼저 보고 "키가 있는지"만 봐서, 센서 데이터 분석(DB)에서 다시 보낸 초음파(`"samplerate": ""`)가 PIEZO로 읽혀 `PIEZO 길이 불일치`로 버려졌다. 지금은 DB 송신도 초음파에 두 키를 넣지 않는다.

디코드에 실패해도 수신은 멈추지 않는다. 로그에 종류·장치·축·seq·오류를 남기고 그 패킷만 건너뛴다(CSV·DB에도 쓰지 않는다).

## 공통 계산

### FFT

기본 창 Blackman. Hann, Hamming, Rectangular, Blackman-Harris, Flat Top, Bartlett, Kaiser(β 기본 8.6). PIEZO 창 목록은 Blackman, Hann, Hamming, Rectangular.

1. 선택 구간에서 평균을 뺀다. Window N이 전체보다 작으면 가운데를 자른다.
2. 창을 곱한다.
3. 단측 크기 `2|rFFT|/Σw`(DC와 짝수 N Nyquist는 2배 안 함) = Count Peak. g Peak = × g/LSB, g RMS = ÷ √2.

**Window 보정**(수신기 V057·발생기 v070): 보정 없음 / 진폭 보정(기본) / 에너지 보정. 보정계수를 화면에 보여 준다. 자세한 식은 `docs/web_db-구성과-데이터흐름.md` "Window 보정".

### 필터

HPF, LPF, Notch는 패킷 하나의 rFFT에 크기만 곱하고 irFFT로 되돌린다(`spectral_filter`, 위상 0).

- HPF·LPF는 Butterworth 크기(−3 dB, 차수 1~12), Notch는 가우시안(폭 = 반치전폭).
- RAW와 FFT에 따로 켠다. 기본은 모두 꺼짐.
- LPF '자동 Fs/2'(기본 켜짐)면 LPF를 걸지 않는다(V057·v070과 같음). 칸마다 계산식을 보여 준다.

### ADXL 단위와 눈금

`g = Count × g/LSB`(0 초과 10 이하). RAW 자동 단위는 세 축을 같이 보고 g / mg / µg 중 하나. FFT 단위는 자동(g RMS), Count Peak, g Peak, g RMS, 속도 mm/s RMS(`g RMS × 9806.65 / (2πf)`, f=0은 0).

gN = 같은 주파수의 `√(X²+Y²+Z²)` 곡선. SRSS 한계선은 FFT 단위가 속도일 때만(장치별, DB `srss_limit`, 기본 4.5 mm/s RMS).

주파수·감도 보정(FFT 표시에만):

```
f_real = f_measure / 1.014
S(f) = 0.99 (f ≤ 60 Hz), 1.07 − 0.0005 × f (60 < f ≤ 360 Hz), 0.89 (f > 360 Hz)
G_real = G_measure / S(f)
```

### PIEZO 단위

기본 Vmax 3.89 V, Amax 4096, 감도 100 mV/g. `K = 1000 × Vmax / Amax`(mV/Count). RAW는 패킷 평균을 뺀 값.

| 단위 | RAW | FFT |
| --- | --- | --- |
| Count | `C − mean(C)` | Count Peak |
| mV | × K | Count Peak × K |
| g RMS | × K / 감도 | Count Peak × K / (감도 × √2) |
| mm/s RMS | (RAW는 g) | bin별 `g RMS × 9806.65 / (2πf)` |

### SRSS

X·Y·Z 단측 peak로 만든 전체 AC RMS 숫자 하나(그래프의 가로 점선).

```
P_axis = Σ(weight × A_peak²) × (Σw)² / (N × Σw²)     (DC 0, 짝수 N Nyquist 1, 나머지 0.5)
SRSS   = √(P_X + P_Y + P_Z)
```

세 축의 Fs·샘플 수가 같아야 한다. 통계(`stats_calc.adxl_set_stats`)는 Blackman 고정, 필터·보정 없이 세트마다 RMS·PEAK·SRSS(g)·SRSS(mm/s)를 낸다.

### PSD(Welch), 속도 RMS 시간 이력

분석 화면 서랍의 PSD를 켜면 FFT 칸이 Welch PSD로 바뀐다(구간 N, Overlap, 목표 구간 수, 합성 SRSS와 한계 판정, 연산 단계 ①~⑥). 'X/Y/Z 속도 RMS 시간 이력'은 세트마다 축별 속도 RMS를 시간 순으로 그린다. 둘 다 발생기 v070과 값이 같다(상대 오차 0으로 확인). 식은 `docs/web_db-구성과-데이터흐름.md` "PSD", "X/Y/Z 속도 RMS 시간 이력".

### FFT 평균, FFT / IFFT 검증

- FFT 평균(분석 화면): 현재 패킷부터 M개(2~128, 전체)의 같은 bin 진폭을 물리 단위로 바꾼 뒤 평균. PSD 모드에서는 쓰지 않는다.
- FFT 과정 / IFFT 검증: `np.fft.fft` → `ifft` 왕복이 `rtol=1e-10`, `atol=1e-8`로 같으면 PASS. 초음파는 위상이 없어 PASS로 보지 않는다.

### 그래프 조작

휠 = X·Y 확대, 왼쪽 버튼+휠 = X만, 오른쪽 버튼+휠 = Y만, 왼쪽 드래그 = 이동, 더블클릭 또는 '그래프 전체 보기' = 자동 범위. 축 대상(RAW/FFT), X/Y 고정, min/max(칸 안 글자), 축 적용/고정, 축 자동.

고정 커서(2026-11-20, 수신기 V057·발생기 v070의 클릭 커서): 곡선을 끌지 않고 클릭하면 35px 안의 가장 가까운 점에 커서를 고정한다. 세로 점선, 점, 그래프 오른쪽 위 값 상자(선 이름, X, Y와 축 단위)가 보인다. 고정하는 것은 '선 이름 + X'라서 새 패킷이 오거나 다른 패킷으로 옮겨도 같은 선의 같은 X에서 지금 Y를 다시 찾는다. 곡선이 없는 곳을 클릭하거나 우클릭 메뉴 '커서 해제'로 푼다. 그래프마다 하나이고, 수신 모니터·두 분석 화면의 RAW/FFT와 속도 RMS 시간 이력 창에 모두 있다(`graph.js` `pinCursor`).
분석 화면은 범례를 그래프 위 제목 줄(RAW / FFT 옆)에 두고 그래프 안 제목은 끈다. 범례 항목을 누르면 그 선을 숨기고/보인다.
점을 브라우저로 보낼 때는 구간마다 최소·최대를 남겨 봉우리가 사라지지 않게 한다(계열당 최대 16384점).

| 데이터 분석 CSV | 파일·XYZ CSV 열기, 앞부분 복구, 패킷 이동, 서랍(설정: 그래프 옵션·PSD·시간 이력·FFT 검증 / 전송: 브로커·토픽·주기·Jitter·Loss·seq 자동) |
| 센서 데이터 분석 | DB에서 MAC·최근 N세트·기간으로 열기, 나머지는 위와 같음 |
| 통계 | MAC별 SRSS 전체 평균 막대·최근 값, RMS·PEAK 구간 그래프, 센서 현황에서 넘어오면 5초 강조, 마지막 계산 시각 |
| 설정 | 장치(이름·SRSS 한계) / 평면도 배치(추가·교체·이름·순서·삭제, 끌어 놓기, 확대, 검색) / 통계 데이터(CSV로 일자별 통계). 수신 연결은 수신 모니터에서 |

이번 점검에서 찾아 고친 것

- 센서 데이터 분석(DB)에서 다시 보낸 초음파가 PIEZO로 오인되어 저장되지 않음 → 송신·수신 양쪽 수정(위 "패킷과 디코드").
- favicon 404 → 빈 응답.

2026-11-20 프로그램과 맞춘 것(점검 기록은 `docs/web_db-반영-점검.md`)

- STOP 뒤 START가 다시 STOP을 보내던 것 → STOP 뒤 센서 타입 칸을 normal(1/2)로 돌린다.
- 측정 주기 0이 1로 바뀌고 소수가 잘리던 것 → 0 이상의 정수만 받는다.
- 센서 명령: QoS 1, 끝 CR LF 없음(JSON 본문만), CR 포함 1024바이트 검사, STOP 3단계(STOP → retain 삭제 → normal, 단계마다 PUBACK).
- 구독 QoS 선택(0/1/2, 기본 1).
- 수신 CSV에 `acqStatus`, `apSsid`, `apRssi` 열, CSV를 열 때 세 값 읽기.
- RAW/FFT·시간 이력 그래프 고정 커서.

알고 있는 한계(고치지 않음)

- 서버 메모리 상태 공유(위 "메모리에만 있는 것"): 여러 사람이 동시에 수신 모니터 옵션이나 분석 화면을 쓰면 서로 덮는다.
- 배터리 값: 지금까지 받은 데이터는 DB·CSV 모두 `batteryRmin` = 0이라 모두 '부족'으로 보인다(센서가 값을 보내기 시작하면 해결).
- 수신 CSV는 ADXL 축이 오는 즉시 쓰고, 디코드 실패 패킷은 HEX도 남기지 않는다(데스크톱과 다름).
