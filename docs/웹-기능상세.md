# 웹 시스템 기능 상세

로컬 웹은 데스크톱 발생기·수신기를 페이지 두 개로 옮긴 것이다. 브라우저는 화면과 그래프 조작만 하고, MQTT·HEX 디코드·FFT·CSV는 이 PC의 파이썬이 한다. 데스크톱 `.py`를 import하지 않는다. 필요한 계산은 `web/core.py`에 복사해 두었다.

실행은 프로젝트 루트에서 다음이다.

```
.venv\Scripts\python.exe -m uvicorn web.server:app --host 127.0.0.1 --port 8080
```

주소는 `http://127.0.0.1:8080/` 이다.

| 주소 | 화면 | 파일 |
| --- | --- | --- |
| `/` | 센서 수신 모니터 | `web/index.html`, `web/static/monitor.js` |
| `/generator` | MQTT 파형 발생기 | `web/generator.html`, `web/static/generator.js` |
| `/monitor` | 모니터와 같은 페이지 | |
| `/archive` | `/` 로 되돌린다. 저장 데이터 전용 페이지는 없다 | |

공통 화면은 `web/static/style.css`, 그래프 조작은 `web/static/graph.js`다. 차트 라이브러리는 `web/static/chart.umd.min.js`와 zoom 플러그인이다. 계산 API는 `web/server.py`, 그래프 수식은 `web/analysis.py`다.

설정 파일은 프로젝트 루트에 있다.

- `mems_lsb_scale.json`: 1 LSB당 g. 없으면 `1/256`.
- `mems_frequency_sensitivity.json`: FFT 주파수·감도 보정.

수신 CSV는 `data_csv/YYYYMMDD_HHMMSS/`다. 실행 시 그 폴더만 만든다. 발생기가 고른 파일은 메모리로 읽고, `web/uploads`에는 남기지 않는다.

## 브라우저와 파이썬의 경계

브라우저가 못하는 일은 파이썬이 한다.

- COM 포트는 열지 않는다. 웹 모니터는 MQTT만 받는다.
- MQTT 클라이언트는 서버 프로세스 안에 하나만 둔다. 페이지를 새로고침해도 브로커 연결은 서버에 남는다.
- 그래프에 그리는 점만 줄인다. HEX, 저장 CSV, 송신 JSON의 `sensorData`는 표시 계산으로 다시 쓰지 않는다.

모니터는 수신 패킷이 계속 들어오므로 1초마다 `/api/monitor/state`를 본다. 발생기가 1초마다 부르는 `/api/generator/status`는 브로커 호출이 아니다. 서버 메모리의 Publish / PUBACK / Drop과 로그만 읽는다. 브로커에 붙는 순간은 연결 테스트와 전송 시작뿐이다.

## 패킷과 디코드

`seq` 상위 nibble이 종류다. 0 PIEZO, 1 ADXL X, 2 ADXL Y, 3 ADXL Z. 하위 nibble은 0~F 순환이다. 함수는 `parse_seq`, `classify_vibration`, 발생기 송신 시 `SequenceState.next_seq`다.

진동 `sensorData`는 HEX다. 4글자마다 signed int16, big-endian이다.

- PIEZO는 `7D 5E → 7E`, `7D 5D → 7D`를 푼 뒤 해석한다 (`decode_piezo_samples`).
- ADXL은 escape를 풀지 않는다 (`decode_vibration_samples`).
- ADXL `samplerate`는 Hz(100~3200)와 레지스터 코드(`0x08`~`0x0F`, 10~15)를 모두 Hz로 바꾼다 (`normalize_sample_rate`).

초음파 H는 시간 파형이 아니다. 12바이트 헤더와 float32 little-endian 320개, 합계 1292바이트다. 헤더 8번 바이트가 시작 kHz, 9번 바이트가 간격 Hz다. 길이가 1292가 아니면 escape를 한 번 풀어 다시 본다 (`decode_ultrasonic_samples`).

초음파로 보는 조건 (`classify_ultrasonic`, 수신기 049와 같다).

- 토픽에 `ultrasonic` 또는 `/ultra`가 있으면 H다.
- 그렇지 않으면 `samplerate`와 `numofsample`이 둘 다 비어 있을 때만 H다.
- 둘 중 하나만 있는 패킷은 불완전한 진동 프레임이다. H로 그리지 않고 로그에 `측정 데이터 아님`을 남긴다.

디코드가 실패하거나 프레임 처리 중 예외가 나도 MQTT 수신 루프는 멈추지 않는다. 로그에 종류, 장치, 축, `seq`, 오류를 적고 그 프레임만 건너뛴다. 초음파 축 표기는 `H`다.

## 공통 계산

### FFT

기본 창은 Blackman이다. Hann, Hamming, Rectangular, Blackman-Harris, Flat Top, Bartlett, Kaiser(β 기본 8.6)가 있다. PIEZO 화면의 창 목록은 Blackman, Hann, Hamming, Rectangular 네 개다.

`fft_peak` / `calculate`에 해당하는 순서 (`fft_peak`):

1. 선택 구간에서 평균을 뺀다. Window N이 전체보다 작으면 가운데를 자른다.
2. 창 `w`를 곱한다.
3. 단측 크기 `2|rFFT|/Σw`. DC와 짝수 N의 Nyquist는 2배하지 않는다.

이 값이 Count Peak다. g Peak는 Count Peak × (g/LSB)이고, g RMS는 그 값을 `√2`로 나눈다.

### 필터

HPF, LPF, Notch는 패킷 하나의 rFFT에 크기만 곱하고 irFFT로 되돌린다 (`spectral_filter`). 위상은 0이고, 패킷 끝을 주기로 보기 때문에 양 끝 누설이 생길 수 있다.

- HPF, LPF: Butterworth 크기, 차단은 −3 dB, 차수 1~12.
- Notch: 가우시안. 폭은 반치전폭.
- RAW와 FFT에 각각 켤 수 있다. 기본은 모두 꺼짐이다. PIEZO LPF 기본 후보는 3000 Hz, ADXL은 1000 Hz, HPF는 10 Hz, Notch는 975 Hz / 폭 20 Hz다.

### ADXL 단위와 눈금

`g = Count × g/LSB`. 허용 범위는 0 초과 10 이하다.

RAW 자동 단위는 세 축을 같이 본다. 최대값이 0.001 g 미만이면 µg, 1 g 미만이면 mg, 그 외는 g다. 축마다 따로 고르지 않는다. Z에 중력이 있으면 g, X/Y만 보면 mg가 되어 한 그래프에서 작은 축이 바닥에 붙기 때문이다. 모니터는 `monitor_adxl_set`이 X/Y/Z를 한 패킷으로 만들어 `_adxl_curves`에 넘긴다.

FFT 자동 단위는 g RMS다. 선택지는 자동, Count Peak, g Peak, g RMS다. 웹 ADXL FFT에는 mm/s RMS 선택지가 없다. PIEZO FFT에는 있다.

주파수·감도 보정은 FFT 표시에만 쓴다. Count Peak에서는 감도 나눗셈을 하지 않는다.

```
f_real = f_measure / 1.014
S(f) = 0.99                  (f ≤ 60 Hz)
S(f) = 1.07 − 0.0005 × f     (60 < f ≤ 360 Hz)
S(f) = 0.89                  (f > 360 Hz)
G_real = G_measure / S(f)
```

기본값은 둘 다 켜짐이다. 화면의 저장 버튼이 `mems_lsb_scale.json`과 `mems_frequency_sensitivity.json`에 쓴다.

시간 영역 AC RMS는 창마다 `√mean((값 − 창 평균)²)`이다. 창이 전체면 패킷 표준편차 한 줄이다. 별도 RMS 차트는 없고, 모니터 상태 문구에 숫자만 나온다.

### PIEZO 단위

기본 Vmax 3.89 V, Amax 4096, 감도 100 mV/g.

```
K = 1000 × Vmax / Amax          (mV/Count)
```

RAW 표시는 패킷 평균을 뺀 값이다.

| 단위 | RAW | FFT |
| --- | --- | --- |
| Count | `C − mean(C)` | Count Peak |
| mV | 위 × K | Count Peak × K |
| g RMS | 위 × K / 감도 | Count Peak × K / (감도 × √2) |
| mm/s RMS | RAW는 g | bin별 `g RMS × 9806.65 / (2πf)`, f>0 |

16bit 수신 코드에 12bit 눈금을 시험 적용한 값이다. 절대전압으로 확정하지 않는다.

### SRSS

X·Y·Z 단측 peak로 만든 전체 AC RMS 숫자 하나다. 주파수마다의 곡선이 아니고 RAW 시계열도 없다. FFT 그래프의 가로 점선이며 색은 `#9467BD`다. 체크 기본값은 켜짐이다.

```
P_axis = Σ(weight × A_peak²) × (Σw)² / (N × Σw²)
SRSS   = √(P_X + P_Y + P_Z)
```

DC 가중치는 0, 짝수 N의 Nyquist는 1, 나머지 bin은 0.5다. 세 축의 Fs, 샘플 수, FFT 길이, 주파수 축이 같아야 한다. 아니면 선을 그리지 않고 `SRSS: 완전한 XYZ 데이터 없음`을 보여 준다.

FFT 평균이 켜져 있으면 진폭을 먼저 평균한 뒤 SRSS를 내지 않는다. 패킷마다 SRSS를 구한 다음 그 숫자를 평균한다. 단위는 현재 FFT 눈금이다. Count Peak이면 Count RMS, g 계열이면 g RMS다.

모니터는 수신된 최신 X/Y/Z 한 세트로 SRSS를 낸다. 발생기는 파일에서 현재 위치부터 평균 개수만큼의 세트를 쓴다.

### FFT / IFFT 검증

버튼 이름은 **FFT 과정 / IFFT 검증**이다. 그래프 설정 안에 있고, 결과는 같은 페이지의 상자에 나온다. 상시 차트는 RAW와 FFT 두 개다. 검증 미리보기는 그 상자 안의 작은 캔버스다.

순서 (`fft_roundtrip_diagnostic`):

1. 입력 실수 배열을 `np.fft.fft`로 보낸다.
2. 같은 복소수 계수를 `np.fft.ifft`로 되돌린다.
3. 양측 크기는 `fftshift(|FFT|/N)`이다.
4. 단측은 DC와 짝수 N Nyquist를 제외하고 2배다.

PASS는 복원 실수부와 입력이 `rtol=1e-10`, `atol=1e-8`로 같을 때다. 최대 오차, RMS 오차, 잔류 허수를 보여 준다. 평균 제거, SRSS, g·mm/s 환산은 검사에 넣지 않는다. 초음파 H는 위상이 없어 PASS로 처리하지 않고, 그 이유를 문장으로 보여 준다.

### FFT 평균

발생기만 파일 패킷을 평균한다. 기본은 꺼짐. 개수는 2, 4, 8, 16, 32, 64, 128, 전체다. 현재 패킷부터 뒤로 M개다.

같은 bin의 peak 진폭을 산술평균한다. RAW 샘플을 평균하지 않고, 평균 곡선을 MQTT로 보내지 않는다. Fs나 길이가 다른 패킷은 빼고 상태 문구에 유효 횟수를 적는다. 초음파에는 평균을 적용하지 않는다.

### 그래프 조작

`GraphView`가 Chart.js 차트에 붙인다.

- 휠: X와 Y를 함께 확대·축소
- 왼쪽 버튼을 누른 채 휠: X만
- 오른쪽 버튼을 누른 채 휠: Y만
- 왼쪽 드래그: 이동. 포인터 캡처를 쓰고, 라이브러리 pan은 꺼 둔다
- 더블클릭 또는 **그래프 전체 보기**: 자동 범위
- 오른쪽 클릭 메뉴
- 축 대상(RAW 또는 FFT), X/Y 고정, min/max, **축 적용/고정**, **축 자동**
- X 눈금 사이에 세로 점선. 눈금은 최대 14개 안쪽

모니터 RAW 시간 축은 초, FFT 주파수 축은 Hz다. 발생기 RAW는 ms, FFT는 kHz다. 계산 함수는 ms·kHz로 내고, 모니터만 초·Hz로 되돌린다.

점을 브라우저에 보낼 때는 구간마다 최소·최대를 남겨 파형의 봉우리가 사라지지 않게 한다 (`_envelope_index`, 상한 16384). 균등 간격으로만 뽑지 않는다. 검증 미리보기는 160점 정도로 따로 줄인다.

색은 X `#1f77b4`, Y `#2ca02c`, Z `#d62728`이다. 발생기 PIEZO는 `#d62728`, 초음파는 `#1377a6`이다. 모니터 PIEZO는 `#1377a6`, 초음파 H는 `#c05b13`다.

장치 선택 첫 항목은 **최근 수신**이다. 값이 비어 있으면 서버의 `latest_device`를 그린다. 목록을 다시 그릴 때 사용자가 고른 MAC이 있으면 그 MAC을 유지한다.

## 센서 수신 모니터

### 연결

기본 브로커 `127.0.0.1`, 포트 `1883`, 구독 `V/#,D/#`다. 연결하면 사용자가 적은 토픽에 `S/#`를 더해 QoS 0으로 구독한다. User, Password 칸은 없고, 서버도 사용자 이름을 요구하지 않는다.

상태 표시 id는 `linkStatus`다. `status`를 쓰면 브라우저의 `window.status`와 겹쳐 스크립트가 죽는다.

`S/`로 시작하는 토픽은 설정 응답으로 저장하고 측정 그래프로 넣지 않는다. 그 외 JSON은 진동 또는 초음파로 분류한다.

MAC 목록에는 `MAC HH:MM:SS (수신 횟수)`만 보여 준다. 디코드에 성공한 뒤에만 횟수와 시각이 올라간다.

### 센서 명령

체크한 MAC과, 칸에 값이 있으면 **MAC 직접 입력**을 대상에 넣는다. 대상 추가 버튼은 없다. 둘 다 없으면 보내지 않는다. 보내기 전에 `{MAC들} 주소로 {동작}하겠습니까?`를 확인한다.

토픽은 `S/{MAC}`, QoS 0이다. retain 명령은 JSON 뒤에 `\r\n`을 붙인다.

| 동작 | SENSORTYPE | 내용 |
| --- | --- | --- |
| STOP | 0 | `COMMPATH=0`, 주기만 포함. retain |
| START, 설정 적용 | 1 PIEZO, 2 ADXL | 샘플 속도·개수와 주기. retain |
| 현재 설정 조회 | | `{"CONFIG":"?"}`, retain 아님. MAC은 1개만 |

`COMMPATH`는 `"0"`으로 고정한다. 주기는 0 이상의 정수 초다.

PIEZO Fs는 512, 1280, 2560, 5120, 12800, 25600 Hz다. ADXL Fs는 100, 200, 400, 800, 1600, 3200 Hz이고, 송신 코드는 `0x08`~`0x0F`다. 개수는 1024, 2048, 4096, 8192다. 화면에서는 `Fs + N` 한 줄로 고른다. ADXL 코드 문자열은 `0x`를 유지한 채 보낸다.

모드 A의 collection(3, 4)과 STOP → retain 삭제 → normal 3단계는 웹에 없다. 시리얼도 없다.

### CSV

**CSV 저장**이 켜져 있으면 연결 시점부터 세션 폴더를 만들고, 수신마다 HEX 파일과 decoded 파일을 쓴다. 측정 START와 무관하다. 행을 쓸 때마다 flush한다. 디코드에 실패하면 그래프에는 안 넣고, HEX 저장도 그 패킷은 타지 않는다. 저장 스레드 오류는 오류 횟수만 올린다.

공통 열: received_at, source, dvicMacAddr, gwMacAddr, sensor_type, axis, seq, tick, batteryRmin, samplerate, numofsample, payload_bytes.

HEX 파일은 `sensorData_hex`를 더한다. decoded는 샘플 개수와 쉼표로 이은 값이다. 초음파 decoded는 minKhz, intervalHz, freq_start_kHz, freq_end_kHz를 더한다.

ADXL은 축 이름이 파일 종류에 들어간다. 데스크톱처럼 X/Y/Z가 한 세트가 될 때까지 기다렸다가 세 파일을 같이 쓰지는 않는다. 축 패킷이 디코드되는 즉시 그 축 파일에 쓴다.

### 그래프 설정

그래프 위 `details`다. 접을 수 있고 기본은 펼침이다. PIEZO 옵션과 MEMS 옵션이 왼쪽·오른쪽에 같이 있다. 둘 중 하나를 숨기지 않는다.

설정이 바뀌면 `/api/monitor/view`로 서버에 올리고, 다음 상태 응답의 곡선을 다시 그린다.

## MQTT 파형 발생기

한 장치 분량의 파일을 읽어, 고른 패킷부터 MQTT로 반복 송신한다. RAW와 FFT는 같은 페이지에 항상 있다. 차트 데이터는 갱신할 때마다 교체하고, 브라우저로 보내는 점은 계열당 16384개를 넘지 않게 줄인다. 별도 그래프 창은 두지 않는다.

### 브로커와 송신

기본 `127.0.0.1:1883`, QoS 1, Device ID `S01`, MAC `TEST00000001`이다. User, Password는 없다.

체크된 센서만 송신한다. 기본 토픽은 PIEZO·ADXL `V/{mac}`, 초음파 `D/{mac}`다. `{mac}`은 MAC 덮어쓰기가 켜져 있으면 입력 MAC, 꺼져 있으면 패킷의 `dvicMacAddr`다. `{device}`는 Device ID다.

**연결 테스트**는 붙었다가 바로 끊는다. **선택 위치부터 전송 시작**은 센서마다 스레드를 만든다.

- 시작 위치는 지금 보고 있는 패킷이다. 파일 끝 다음은 1번이 아니라 그 시작 위치로 돌아간다.
- 자동 주기가 켜져 있으면 주기(ms)는 `numofsample / samplerate × 1000`이다. 초음파는 자동 주기가 없고 기본 10000 ms다. PIEZO 기본 주기 칸은 320 ms, ADXL은 2560 ms다.
- ADXL은 X, Y, Z 순서로 보내고 축 사이에 XYZ gap(기본 5 ms)을 둔다.
- Jitter와 Loss%는 기본 꺼짐이다. Loss는 그 확률로 publish를 건너뛰고 Drop에 센다.
- 진동 seq 자동이 켜져 있으면 `seq`를 다시 만든다.
- 초음파 tick 증가가 0이 아니면 송신 횟수만큼 tick을 더한다.
- 부분 복구된 ADXL HEX는 미리보기만 되고 publish에서 빠진다.

데스크톱 발생기가 송신 직전에 채우는 `acqStatus=OK`, `apSsid=REPLAY`, `apRssi=0`은 웹 송신에 없다. 파일에 있는 필드는 그대로 나간다.

중지하면 스레드를 기다리고 브로커 연결을 닫는다. 화면의 Publish / PUBACK / Drop은 1초마다 상태 API를 읽어 고친다.

### 파일

센서마다 파일 하나다. JSON, JSONL, 수신기 HEX CSV를 읽는다.

ADXL은 X/Y/Z CSV 세 개를 **XYZ CSV 로드**로 한 세트로 맞춘다. **손상된 HEX 앞부분 자동 복구**는 미리보기 전용이다. 깨진 문자열의 앞쪽 완성 16bit만 남기고, 뒤를 추측하거나 0으로 채우지 않는다. 원본 CSV는 수정하지 않는다.

고른 파일은 임시 파일로 파싱한 뒤 바로 지운다. 재생 목록은 서버 메모리에만 있다. 실패하면 HTML이 아니라 JSON 오류를 돌려 브라우저 알림에 그대로 나오게 한다.

패킷 이동은 이전, 다음, 번호 이동이다. 그래프 센서와 메인 센서 선택은 같은 위치를 본다.

### 그래프 설정

그래프 창 안에서 캔버스보다 위에 있다. 접을 수 있다. PIEZO와 MEMS가 나란히 보인다. 발생기에도 SRSS, Blackman 기본 창, FFT 검증, FFT 평균, 회전 부품 후보가 있다.

회전 후보는 RPM(기본 1800)과 축을 넣어 2~48배 차수가 FFT 피크와 맞는 정도를 점수로 보여 준다. 부품 종류를 확정하지 않는다. 유형 목록은 표시용이다.

## 데스크톱에만 있는 기능

웹에 넣지 않은 것이다.

- PyQtGraph 별도 프로세스와 늦은 프레임 버리기. 웹은 Chart.js다.
- 시리얼 포트.
- MQTT User / Password.
- 모드 A `SENSORTYPE` 3·4와 STOP → retained 삭제 → normal 세 단계, QoS 1 PUBACK 대기.
- ADXL FFT의 mm/s RMS.
- 재생 송신 시 비어 있는 `acqStatus` / `apSsid` / `apRssi`를 OK, REPLAY, 0으로 채우기.
- PIEZO 장치별 Vmax 파일, g RMS 보정(`counts_per_g`), SciPy 비교 그래프.
- 초음파·PIEZO·ADXL을 각각 다른 그래프 창으로 열기. 웹은 한 화면의 RAW·FFT 두 개다.
- 모니터가 ADXL X/Y/Z를 한 세트로 모은 뒤에만 CSV에 쓰기.

## 웹에만 있는 동작

- 페이지 두 개와 상단 메뉴.
- 브라우저 휠·드래그·축 고정.
- 모니터 그래프 기본 장치 **최근 수신**.
- 명령 전 MAC 확인 문구.
- 발생기 상태 숫자를 1초마다 HTTP로만 갱신.
- 업로드 실패를 JSON으로 반환.
- 점 축소 때 min/max를 남겨 FFT 봉우리와 RAW 파형을 유지.
