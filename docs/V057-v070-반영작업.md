# 수신기 V057 · 발생기 v070 웹 반영 작업

데스크톱 수신기 `new_piezo_adc_V057_window_ratio_fix.py`와 발생기 `mqtt_wave_replay_generator_v070_pyqtgraph_rms_history_xy_zoom_pin.py`에서 새로 생긴 기능을 `web_db`(8081)에 옮긴 내역이다. 항목마다 바꾼 파일, 화면에서 보이는 곳, 확인한 방법을 적었다. 동작 설명은 `docs/web_db-구성과-데이터흐름.md`에 있다.

아직 커밋하지 않았다. 서버를 다시 켠 뒤 브라우저에서 Ctrl+F5로 새로고침하면 반영된다.

## ① Window 보정

- 서버
  - `web_db/src/signal.py`: `window_correction_mode`, `window_correction_ratio`, `window_correction_label`, `srss_window_ratio`, `srss_mode_text`. `fft_peak(…, correction=)`.
  - `web_db/src/graph_curves.py`: 표시 FFT, FFT 평균, gN에 모드 적용. SRSS는 `보정 없음`일 때만 √mean(w²)² 곱함. 응답에 `window_correction`, `window_factor`.
  - `web_db/src/graph_options.py`: 기본값 `window_correction: 진폭 보정`(PIEZO, ADXL).
  - `web_db/src/view_pack.py`, `web_db/src/monitor_service.py`: 보정계수 문구를 화면까지 전달.
- 화면
  - 서랍 `partials/drawer.html`: PIEZO `piezoWindowCorrection` + `piezoWindowFactor`, MEMS `adxlWindowCorrection` + `adxlWindowFactor`.
  - 수신 모니터 `index.html` 그래프 설정: 같은 id의 칸.
  - `generator-draw.js`, `monitor-draw.js`: 옵션 전송, 보정계수 문구 표시.
- 바뀌지 않는 것: 기본이 `진폭 보정`이라 예전 그래프와 통계(`stats_calc`) 값은 그대로다.
- 확인
  - v070 함수와 세 모드 × 창 네 종류(Blackman, Hann, Kaiser, Flat Top) 결과가 같다.
  - ADXL mm/s SRSS: 보정 없음 38.95, 진폭·에너지 70.58 mm/s. 비율 0.552 = Blackman √mean(w²).

## ③ PSD (Welch)

- 서버
  - `web_db/src/signal.py`: `welch_packet_psd` (v070과 같음. 구간을 하나도 못 쓰면 nan 대신 오류).
  - `web_db/src/graph_psd.py` (새 파일): `psd_settings`, `base_unit`, `axis_psd`, `packet_psd`, 연산 단계 문구.
  - `web_db/src/graph_curves.py` `generator_curves`: `options.psd.on`이면 FFT 평균을 건너뛰고 FFT 칸·gN·SRSS를 PSD 결과로 바꿈. 정보 칩에서 FFT peak를 빼고 축별 PSD RMS를 넣음. 실패하면 RAW는 그리고 PSD 칸에 오류 문구.
  - `web_db/src/graph_options.py`: 기본값 `psd: {on: false, segment: 전체, overlap: 50, target: 30}`.
  - `web_db/src/view_pack.py`: `psd` 결과(SRSS, 한계값, 판정, 단계, 축별 RMS)를 응답에 담음.
- 화면
  - 서랍 `FFT 평균` 아래 점선 상자: `PSD (Welch)`, `PSD 구간 N`, `Overlap (%)`, `PSD 평균 목표 구간`, 안내 문구.
  - 그래프 위 `PSD RMS 요약 / 장치별 한계값 판정` 칸(`partials/psd-history.html`): 합성 SRSS, 속도 한계값, 판정 배지(정상 초록 / 초과 빨강 / 비교 안 함 회색), 접히는 `PSD 연산 단계 ①~⑥`.
  - FFT 그래프: 제목 `PSD | Window=… | 구간 N=… | Δf=…`, 세로축 `(단위)²/Hz`, gN 자리에 `XYZ 합성 PSD`.
- v070과 같은 규칙
  - PSD일 때 `FFT 평균 적용`·평균 개수는 패킷 범위로만 쓴다(꺼져 있으면 선택 패킷 하나).
  - Fs·샘플 수가 선택 패킷과 다른 패킷은 건너뛴다. 구간 수로 가중 평균한다.
  - 합성 SRSS는 그래프에 선으로 그리지 않는다(밀도 단위가 아님). 한계 비교는 mm/s일 때만.
- 확인: v070 `Generator._plot_packet_psd`를 직접 호출해 비교했다. ADXL(mm/s, 자동 g RMS, Count Peak), PIEZO(mV, mm/s, Count) 여섯 경우에서 곡선(상대 오차 0), 합성 SRSS 문구, 상태 문구가 모두 같다.

## ④ X/Y/Z 속도 RMS 시간 이력

- 서버

  - `web_db/src/replay.py` `velocity_history`: 올려 둔 ADXL 세트를 복사해 잠금 밖에서 계산, 로그 `[RMS 시간 이력] …`.

  - `web_db/src/grouping.py` `packet_to_template`: DB 패킷에도 `_received_at`(수신 시각), `_packet_no`(`set_no`). 그래서 `/studio`에서 연 DB 세트도 시간 이력을 쓸 수 있다(v070에는 없는 확장).
  - `_`로 시작하는 키는 송신 때 `replay._publish`가 뺀다(예전과 같음).
- 화면
  - 서랍 PSD 상자 안 `X/Y/Z 속도 RMS 시간 이력` 버튼 → 가운데 창(`historyModal`).
  - 시작 세트(기본 = 지금 패킷 번호), 세트 수(빈칸 = 끝까지), `다시 계산`, `그래프 전체 보기`, `닫기`(Esc·바깥 클릭도 닫음).
  - 차트: X, Y, Z, SRSS, 한계값 점선. 한계 초과 SRSS 점은 빨간 큰 점. 점 위에 세트·packet_no·수신 시각. 휠 확대·드래그는 RAW/FFT와 같음.
  - 표: 세트, packet_no, X received_at, X/Y/Z/SRSS mm/s, 판정. 줄을 누르면 메인 그래프가 그 세트로 이동.
  - `제외 세트 n건`: 축 누락, 수신 시각 없음, PSD 구간 부족 사유.
  - 스크립트 `web_db/front/static/velocity-history.js`, 테마는 `theme.js`의 `SensorTheme.watch`.
- 확인: 실제 CSV 8세트 × 설정 6가지(HPF 켜고 끔 × 구간 전체/512/1024)에서 v070 결과와 X/Y/Z/SRSS가 같다. DB 20세트로 HTTP 호출 성공.

## ⑤ ADXL CSV packet_no

배경: 센서 seq는 MAC 하나에 카운터 하나지만 축마다 1씩 오른다(X `1A` → Y `2B` → Z `3C` → 다음 X `1D`). 그래서 seq로 묶으면 축이 빠져도 다음 세트가 어긋나지 않는다. CSV의 `packet_no`는 seq가 아니라 CSV를 쓰는 쪽이 붙이는 행 번호라서 따로 맞춰야 한다.

- 저장 `web_db/src/save_csv.py`
  - 예전: 축 파일마다 따로 셈. Z 하나가 빠지면 그 뒤 X/Y/Z 번호가 모두 어긋남.
  - 지금: ADXL은 `grouping.continues_set`(DB `set_no`와 같은 규칙)으로 정한 세트 번호. 축이 빠진 세트는 그 번호 행이 일부 파일에만 있고, 다음 번호는 세 축이 다시 같이 씀. PIEZO·초음파는 예전처럼 행 번호.
- 읽기 `web_db/src/load_file.py`
  - 세 파일 모든 행에 숫자 `packet_no`가 있으면 `(MAC, packet_no)`로 묶음(v070). 축 누락·중복, 디코드 실패, 수신 순서·30초 이탈은 제외.
  - 웹 보완: 같은 번호 X/Y/Z의 seq 하위 4비트가 a, a+1, a+2가 아니면 그 파일 `packet_no`는 세트 번호가 아니라고 보고 seq 방식으로 다시 묶는다(예전 웹 CSV 대비).
  - `packet_no`가 없으면 예전 seq 방식.
  - 송신 로그 첫 줄에 `[ADXL 묶음: packet_no + MAC + seq + received_at(30초)]` 또는 `[ADXL 묶음: seq + received_at 순서]`, 제외 세트 수.
- 바뀌는 점: `packet_no` 방식으로 묶이면 축이 빠진 세트는 목록에서 빠진다(v070과 같음). seq 방식은 예전처럼 남는다.
- 확인: 웹 저장기로 "XYZ, XY(Z 손실), XYZ, YZ(X 손실), XYZ"를 써 보니 X `1,2,3,5`, Y `1,2,3,4,5`, Z `1,3,4,5`. 읽으면 1·3·5번만 남고 2·4번은 사유와 함께 제외. 같은 데이터를 예전 방식(축마다 따로 센 번호)으로 바꾸면 seq 검사에 걸려 seq 방식 5세트(부분 2)로 자동 전환.

## ⑥ 필터 계산식, LPF 자동 Fs/2

- `web_db/front/static/filters.js` (새 파일): 필터 줄 HTML, 읽기, 계산식 문구. 예전에 `monitor-draw.js`와 `generator-draw.js`에 같은 코드가 두 벌 있던 것을 하나로 합쳤다.
  - 줄 아래 문구 예: `RAW OFF · FFT ON | |H(f)|=1/√(1+(10/f)^(2×4)), f>0`
  - 값 칸 이름을 `차단 Hz`/`차수`, Notch는 `중심 Hz`/`폭 Hz`로 바꿨다.
- LPF `자동 Fs/2` (기본 켜짐, V057·v070과 같음)
  - 켜져 있으면 `lp_cutoff=None` → `signal.spectral_filter`가 LPF를 건너뜀(차단 = Nyquist = 전 대역 통과). 값 칸은 잠김.
  - 서버 `graph_options._filter_kwargs`, 기본값 `LPF.auto: true`. 계산식 줄에 `LPF(자동 Fs/2→우회)`. PSD 단계 ②에 `LPF=Fs/2 상한(실제 필터 우회)`.
  - 바뀌는 점: 예전에는 LPF를 켜면 바로 3000/1000 Hz가 걸렸다. 이제 직접 차단 주파수를 쓰려면 `자동 Fs/2`를 끈다.
