# web_db 화면 역할

기준은 `http://127.0.0.1:8081` 프로세스다. 실행은 프로젝트 루트에서 다음이다.

```text
.\.venv\Scripts\python.exe -m uvicorn web_db.server:app --host 127.0.0.1 --port 8081
```

8080의 `web` 폴더는 CSV 수신 프로그램이다. 8081은 `web_db`다. 내부 구성과 데이터 흐름은 `docs/web_db-구성과-데이터흐름.md`에 있다.

| 위치                     | 내용                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| `web_db/server.py`       | 실행 진입점. `uvicorn web_db.server:app`                                                   |
| `web_db/src`             | 역할별 파이썬. `server.py`는 HTTP 입구만 둔다                                              |
| `web_db/src/routes`      | 주소별 API. 화면, `/api/generator`, `/api/monitor`, `/api/analysis`, `/api/db`             |
| `web_db/src/save_csv.py` | 수신 CSV 저장                                                                              |
| `web_db/front`           | HTML과 `/static` 화면 파일. 스크립트 역할은 `docs/web_db-구성과-데이터흐름.md`의 화면 스크립트 절 |
| `web_db/sensor.sqlite`   | 패킷, 이름, 설정 JSON, 통계. git에 넣지 않는다. 없으면 서버가 켜질 때 테이블과 함께 만든다 |

## 데이터가 저장되는 곳

센서 수신 모니터가 MQTT에 연결되면 측정 패킷은 두 곳에 남는다.

| 저장                              | 내용                                                                          | 언제                                                              |
| --------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `data_csv/YYYYMMDD_HHMMSS/`       | HEX CSV, decoded CSV                                                          | 연결할 때마다 폴더 하나. 연결이 유지되는 동안 그 폴더에 계속 쓴다 |
| `web_db/sensor.sqlite`의 `packet` | CSV 한 줄과 같은 원본. MAC, 시각, 축, seq, 샘플링, HEX, 디코드 샘플, `set_no` | 패킷이 디코드될 때마다 한 줄. session 은 쓰지 않는다              |

ADXL X/Y/Z는 축마다 한 줄이다. 같은 측정은 `set_no`가 같다. seq 상위 4비트는 축이고, 하위 4비트는 축을 보낼 때마다 1씩 증가한다. `10`, `21`, `32`가 한 세트다.

통계 숫자인 SRSS, RMS, PEAK는 이 시점에 만들지 않는다. 하루 한 번(자정 뒤) 스케줄러가 돌 때, 마지막 통계 뒤에 들어온 완성 세트만 읽어 `measurement`에 구간 한 줄을 추가한다. 이전 구간은 남긴다.

## 화면별 역할

### 센서 현황 `/` (대문)

평면도 이미지 위에 센서 아이콘을 놓고 센서마다 연결, 수신, 알람을 본다. 계획과 정한 것은 `docs/대문-평면도-대시보드-계획.md`.

- 아이콘 몸통 색은 연결 상태다. 정상(초록), 지연(노랑), 끊김(진회색). 수신 꺼짐, 측정 중지, 기록 없음, 주기 미상은 연회색이다.
- 바깥 고리는 알람이다. 초과(빨강, 깜빡임), 주의(주황). 통계 화면과 같은 값(쌓인 `measurement`의 SRSS 전체 평균)과 같은 기준이다. 최신화는 하지 않는다.
- 연결 판정은 마지막 수신 후 경과 시간을 원래 간격과 비교한다. 원래 간격은 실제 측정 간격의 중앙값이고(ADXL은 X→Y→Z 한 세트를 측정 한 번으로 센다), 없으면 설정 `SENSING_PERIOD`를 쓴다. 기준값은 임시이고 `site_status.py` 맨 위에 있다.
- 아이콘이나 목록을 누르면 정보 카드(마지막 수신, 원래 간격, 설정, 배터리, SRSS/한계)가 뜬다.
- 평면도는 여러 장이다(층·구역마다 한 장). 평면도 위 탭으로 고르고, 탭에는 그 평면도의 센서 수와 문제 배지(알람 초과 빨강, 주의 주황, 지연·끊김 회색)가 붙는다. 고른 탭은 브라우저가 기억한다.
- 평면도 한 장에는 센서를 여러 개 놓는다. 센서 하나는 평면도 한 장에만 놓인다(다른 평면도에 놓으면 그쪽으로 옮겨진다).
- 위쪽 개수 칩을 누르면 그 상태 아이콘만 강조한다(개수는 모든 평면도 합계). 오른쪽 목록은 전체, 이 평면도, 배치 안 됨, 문제 있음으로 거른다. 다른 평면도에 놓인 센서는 그 평면도 이름이 보이고, 누르면 그 탭으로 옮겨 카드를 띄운다.
- '배치 편집'에서 평면도 추가(PNG, JPG, WEBP, SVG, 15MB 이하, 이름을 묻는다), 지금 평면도의 이미지 교체·이름 바꾸기·탭 순서(◀ ▶)·삭제를 한다. 이것들은 바로 서버에 반영된다.
- 목록의 센서를 지금 평면도로 끌어 놓고, 아이콘을 끌어 옮기고, ×로 뺀다. 위치는 '저장'을 눌러야 서버에 남는다.
- 15초마다 `/api/site/status`를 읽는다. 탭이 안 보이면 멈춘다.

### 센서 수신 모니터 `/receiver`

예전에는 `/` 주소였다. 대문이 생기면서 `/receiver`로 옮겼다.

살아 있는 수신과 센서 명령이다.

- 브로커에 연결하고 `V/#`, `D/#`와 설정 토픽 `S/#`를 구독한다.
- 들어온 파형을 RAW, FFT로 바로 본다. 이 그래프용 계산은 저장 통계와 별개다.
- CSV와 `packet` 테이블에 원본을 남긴다.
- 센서 설정을 `S/{MAC}`에 retain으로 보낸다. 센서 타입 0~4, 주기, Fs+N, G Range, PIEZO 게인이 JSON에 들어간다. 설정 적용과 START는 센서 타입 칸에서 고른 값 그대로 보낸다(수신기 V057과 같음). STOP은 0이다.
- retain으로 보낸 JSON은 `sensor_config`에 그 MAC 기준으로 남긴다. 구독 중 `S/{MAC}`로 들어온 설정(브로커 retain, 데스크톱 수신기가 보낸 것 포함)도 내용이 바뀌었을 때 `retain 수신`으로 남긴다. 현재 설정 조회(`CONFIG ?`) 요청은 저장하지 않는다.
- MAC에 표시 이름을 붙여 `device`에 저장한다. 목록에 없는 MAC도 직접 입력하면 설정 적용과 이름 저장을 할 수 있다. 패킷이 아직 없어도 이름과 설정 JSON은 남는다.
- 이름과 SRSS 한계를 장치 전체로 고치는 화면은 설정 `/settings`다.

### 설정 `/settings`

수신 MQTT 자동 연결 값과, 저장된 MAC의 표시 이름과 SRSS 한계를 넣고, 고치고, 지운다.

- 수신 MQTT: Broker, Port, 구독 Topic, CSV 저장, 서버 시작 때 자동 연결. `app_setting`의 `mqtt`에 저장한다. 자동 연결을 켜고 저장하면 바로 그 값으로 다시 붙고, 서버가 켜질 때마다 붙는다. 브로커가 꺼져 있으면 계속 다시 시도한다. CSV 저장은 기본 꺼짐이다(계속 붙어 있으므로 켜면 CSV가 계속 쌓인다). SQLite에는 항상 저장한다.

- 이름은 `device.display_name`이다. 수신 기록이 있는 MAC은 이름만 지우고, 기록이 없는 MAC은 목록에서도 뺀다.
- SRSS 한계는 `srss_limit`에 저장한다. 통계 막대와 그래프 기준선이 이 값을 읽는다. 줄이 없으면 4.5 mm/s RMS다.

### 센서 데이터 분석 `/studio`

수신으로 쌓인 DB 패킷만 연다. 파일 선택은 없다.

- MAC을 고르고, 최근 N세트 또는 시작~끝 기간으로 연다. 한 번에 최대 200세트다.
- ADXL은 X/Y/Z가 갖춰진 `set_no`만 연다. 기간을 잘라도 세트가 쪼개지지 않는다.
- 그래프에서 PIEZO, MEMS, 초음파를 고르면 그 센서의 설정과 전송 주기만 보인다.
- 전송 체크와 Topic 입력칸은 없다. Topic은 PIEZO·MEMS `V/{mac}`, 초음파 `D/{mac}`을 서버가 넣는다.
- 전송 시작은 지금 열어 둔 DB 패킷을 고른 위치부터 브로커로 반복 송신한다.

### 데이터 분석 CSV `/generator`

화면 배치는 센서 데이터 분석과 같다. 데이터만 파일·CSV다. SQLite는 읽지 않는다. 외부 CSV를 열어 자세히 보고, 그 파일을 MQTT로 다시 보낸다.

### 통계 `/dashboard`

`measurement`에 이미 들어 있는 값만 그린다. 페이지를 열 때 한 번 읽고, 반복 조회는 하지 않는다. 값은 최신화 때만 바뀌기 때문이다. 열어 둔 동안 하루 스케줄러가 돌았으면 페이지를 다시 열면 반영된다.

- 한 줄이 MAC 하나다. SRSS 막대와 RMS 숫자는 구간을 세트 수로 가중한 전체 평균이고, PEAK 숫자는 최댓값이다. 작은 그래프는 최신화 구간의 RMS와 PEAK 변화다.
- 최신화 버튼은 없다(2026-11-18). 사람마다 다른 시각에 최신화하면 보는 값의 기준이 달라지기 때문이다. 화면 위에 `마지막 계산 YYYY-MM-DD HH:MM`을 보여 준다.
- 서버가 켜져 있는 동안, 마지막 최신화 날짜가 오늘보다 이전이면 약 10분 간격 확인 뒤 하루에 한 번 같은 최신화를 한다. 이 스케줄러는 프로세스에 하나뿐이다.
- 최신화는 한 번에 하나만 돈다. 최신화 버튼과 스케줄러가 겹치면 뒤의 것은 앞의 것이 끝날 때까지 기다리고, 그 뒤에 들어온 세트만 넣는다. 같은 구간이 두 번 들어가지 않는다.

## 테이블

| 테이블          | 역할                                            |
| --------------- | ----------------------------------------------- |
| `device`        | MAC, 표시 이름, 마지막 수신 정보                |
| `packet`        | 수신 원본. 통계 계산 전                         |
| `sensor_config` | 그 MAC에 마지막으로 retain 전송한 설정 JSON     |
| `measurement`   | 최신화 구간마다 SRSS, RMS, PEAK 한 줄. 전체 값은 화면에서 가중 평균 |
| `stat_cursor`   | MAC마다 통계가 이미 읽은 마지막 packet id. 계산에 실패한 세트도 다시 읽지 않는다 |
| `stat_meta`     | 통계를 마지막으로 만든 시각                     |
| `srss_limit`    | 설정 화면의 MAC별 SRSS 한계. 없으면 4.5 mm/s RMS |

## CSV 분석과 DB 분석

데이터 출처는 화면마다 하나다.

- 데이터 분석 CSV `/generator`는 외부 파일만 연다. SQLite는 읽지 않는다.
- 센서 데이터 분석 `/studio`는 DB 패킷만 연다. 파일 선택은 없다.
- 둘 다 같은 그래프와 MQTT 재전송을 쓴다. 계산과 송신 스크립트는 `generator-draw.js`, `generator-api.js`다. DB를 고르는 스크립트는 `db.js`다.
- 센서 수신 모니터는 받아서 저장하고 명령을 보낸다. 통계는 `measurement`만 본다. 설정은 이름과 SRSS 한계만 다룬다.
