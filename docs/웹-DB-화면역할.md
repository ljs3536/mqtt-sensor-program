# web_db 화면 역할

기준은 `http://127.0.0.1:8081` 프로세스다. 실행은 프로젝트 루트에서 다음이다.

```text
.\.venv\Scripts\python.exe -m uvicorn web_db.server:app --host 127.0.0.1 --port 8081
```

이 PC에서 바로 띄울 때 8081, Docker(운영)는 8060이다. 예전 `web` 폴더(8080)는 지웠다(2026-11-27). 내부 구성과 데이터 흐름은 `docs/web_db-구성과-데이터흐름.md`에 있다.

| 위치                     | 내용                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| `web_db/server.py`       | 실행 진입점. `uvicorn web_db.server:app`                                                   |
| `web_db/src`             | 역할별 파이썬. `server.py`는 HTTP 입구만 둔다                                              |
| `web_db/src/routes`      | 주소별 API. 화면, `/api/generator`, `/api/monitor`, `/api/analysis`, `/api/db`             |
| `web_db/src/save_csv.py` | 수신 CSV 저장                                                                              |
| `web_db/front`           | HTML과 `/static` 화면 파일. 스크립트 역할은 `docs/web_db-구성과-데이터흐름.md`의 화면 스크립트 절 |
| `web_db/sensor.sqlite`   | 패킷, 이름, 설정 JSON, 통계. git에 넣지 않는다. 없으면 서버가 켜질 때 테이블과 함께 만든다 |

## 데이터가 저장되는 곳

센서 수신 모니터가 MQTT에 연결되면 측정 패킷은 두 곳에 남는다.

| 저장                              | 내용                                                                          | 언제                                                              |
| --------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `data_csv_web/YYYYMMDD_HHMMSS/`       | HEX CSV, decoded CSV                                                          | 연결할 때마다 폴더 하나. 연결이 유지되는 동안 그 폴더에 계속 쓴다 |
| `web_db/sensor.sqlite`의 `packet` | CSV 한 줄과 같은 원본. MAC, 시각, 축, seq, 샘플링, HEX, 디코드 샘플, `set_no` | 패킷이 디코드될 때마다 한 줄. session 은 쓰지 않는다              |

ADXL X/Y/Z는 축마다 한 줄이다. 같은 측정은 `set_no`가 같다. seq 상위 4비트는 축이고, 하위 4비트는 축을 보낼 때마다 1씩 증가한다. `10`, `21`, `32`가 한 세트다.

통계 숫자인 SRSS, RMS, PEAK는 이 시점에 만들지 않는다. 매시간(정각 뒤 1분 안, 2026-11-23 전에는 하루 한 번) 스케줄러가 돌 때, 마지막 통계 뒤에 들어온 완성 세트만 읽어 `measurement`에 MAC·시간마다 한 줄로 넣거나 합친다. 계산 기준은 설정 > 통계 데이터 > '통계 계산 기준'의 지금 버전이다.

## 화면별 역할

**이름 없는 MAC은 보이지 않는다**(2026-11-24). 설정 > 장치에서 이름(`device.display_name`)을 붙인 센서만 '등록된 센서'로 본다. 이름이 있어도 설정 > **장치 표시** 탭의 **'화면 표시'** 체크(`device.visible`, 기본 켬, 누르는 즉시 저장 `POST /api/db/device-visible`)를 끄면 아래 '안 보임' 화면에서 똑같이 숨는다. 이름이 없는 줄은 체크 칸이 꺼져 있다.

**종류별 표시**(2026-11-25): 설정 > **장치 표시** 탭의 PIEZO · MEMS · 초음파 칸. 그 센서가 실제로 보낸 적 있는 종류에만 체크 칸이 생긴다(받은 적 없으면 –). 끄면 그 종류만 센서 현황 판정·아이콘, 통계 화면 줄, 센서 데이터 분석 목록(그 종류 탭)에서 빠진다. 저장·통계 계산·수신 판정은 그대로다. **이미 다른 종류가 있는 MAC에 새 종류가 들어오면 기본으로 숨기고** 주황색 '새'를 붙인다(체크하면 보이고 '새'가 없어짐). 운영 CSV에 다른 종류가 섞여 있어도 시연 화면이 깔끔하게 하려는 것이다. 값 규칙은 [DB 명세서 '종류별 표시'](web_db-DB명세서.md).

| 화면 | 이름 없는 MAC |
| --- | --- |
| 센서 현황(목록·요약 수·평면도 배치 목록·상태 변화 기록) | 안 보임(`store_site.site_rows`에서 뺌) |
| 센서 데이터 분석 MAC 선택 | 안 보임(`/api/db/devices?named=true`). 선택 상자는 '이름 · MAC' |
| 통계 `/dashboard`(통계 2 화면, 옛 화면은 `/dashboard-old`) | 안 보임(`store_query.dashboard`) |
| 설정 > 장치 표, 센서 수신 모니터 | **보임**(MAC을 보고 이름을 붙이는 곳) |

수신 저장과 매시 통계 계산은 이름과 상관없이 그대로 한다. 이름을 붙이면 그 전 기록·통계까지 바로 보인다. 데이터를 보내는 이름 없는 센서는 센서 수신 모니터의 수신 시각으로 알 수 있어, 센서 현황에 따로 알림은 두지 않는다(사용자 결정).

모든 화면 헤더 왼쪽의 White / Gray / Dark 버튼(알약 모양 세 칸, `theme.js`)으로 화면 색을 바꾼다. 새로고침 없이 바로 바뀌고(열어 둔 분석 데이터가 남는다) 브라우저에 기억된다.

### 센서 현황 `/` (대문)

보기 전용이다. 평면도 위 아이콘 색 하나로 센서 상태를 본다. 계획과 정한 것은 `docs/대문-평면도-대시보드-계획.md`.

- 진동 판정은 **ISO 20816-3 Group 2(강성 지지) 네 구간**이다(2026-11-23, 가장 최근 한 시간 통계의 SRSS mm/s RMS).
  양호 < 1.4 ≤ 주의(ISO B 허용) < 2.8 ≤ 경고(ISO C 개선) < 4.5 ≤ 위험(ISO D). 경계는 MAC마다 설정 > 장치에서 바꾼다(아래 '설정').
  경계값은 위 구간에 넣는다(1.4는 주의, 2.8은 경고, 4.5는 위험). 예전에는 한계의 80% 이상 = 경보, 한계 이상 = 위험 두 단계였다.
- 상태는 여덟 가지 하나로 보인다(서버 `site_status.overall_state`가 연결·진동 두 판정 중 나쁜 쪽으로 줄인다).
  나쁜 것부터: 위험(빨강, 깜빡임) / 미수신(진회색) = 원래 간격×2+30초보다 오래 수신 없음 / 경고(주황) / 지연(노랑) = 한 번 빠짐 /
  주의(올리브) / 양호(초록) / 정상(청록) = 제때 수신, 진동 판정 기준이 없는 센서(Type1·Type3) 또는 통계 전 MEMS / 확인 불가(연회색) = 수신 꺼짐·측정 중지·데이터 없음 등.
  위험·경고는 마지막 통계라 수신이 끊겨도 보이고, 주의·양호는 제때 수신 중일 때만 보인다(끊긴 센서가 '양호'로 보이지 않게).
- Type2(MEMS)와 Type1(PIEZO)이 진동 판정을 한다. PIEZO는 **2026-11-25부터** 최근 한 시간 통계 Vrms를 설정 > 장치의 그 MAC 기준(기본 위험 4.5 mm/s, 통계 화면 기준선과 같은 값)으로 MEMS와 같은 네 구간에 넣는다(`site_status.JUDGED_KINDS = ("ADXL", "PIEZO")`). 그 전에는 판정하지 않아 위쪽 '진동' 상태 칸 합계가 총 개수보다 PIEZO 수만큼 적게 보였다. 환산(Vmax·Amax·감도·게인)이 확정되면 그 MAC 기준만 설정에서 조정한다. Type3(초음파)는 통계가 없어 제때 수신 중이면 '정상'.
- 센서 종류 이름: **Type1 = PIEZO 진동, Type2 = MEMS(ADXL) 진동, Type3 = 초음파**(펌웨어 SENSORTYPE 1·2 번호와 맞춤).
- 위쪽 요약은 **진동(Type1·Type2) / 초음파(Type3)** 두 카드이고, 카드 하나가 한 줄이다(머리 글자는 '진동'·'초음파'만, Type 글자는 붙이지 않음 — 2026-11-24): '이름 총 N개 | 상태 [양호 n] [주의 n] [경고 n] [위험 n] | 수신 [정상 n] [이상 n] [확인 불가 n]'(이상 = 지연+미수신). 기준이 없는 종류도 '기준 없음' 글씨 없이 네 구간 개수만 보인다(지금은 0, 기준이 생기면 같은 자리에 더해진다). 칩을 누르면 그 묶음·상태 센서만 강조하고 목록도 거른다. 다시 누르면 풀린다.
- 아이콘 하나로 상태를 보인다: 색 = 상태, 안 그림 = 종류(진동 물결 / 초음파 원), 오른쪽 위 빨간 '!' = 배터리 부족. 평면도 아이콘·목록·정보 카드에 같은 아이콘을 쓴다. 목록 오른쪽에는 상태 글씨 알약과 배터리.
- 평면도 아래 범례: 상태 색 8개, '! 배터리 부족', 종류 그림(Type1·Type2·Type3), 'ⓘ 판정 기준'.
- 수신(MQTT)이 꺼져 있을 때만 노란 안내 줄이 뜬다. 오른쪽 위 점이 초록이면 수신 중.
- 오른쪽 목록은 나쁜 상태부터 정렬되고, 한 줄에 이름과 수신 정보 한 줄(예: "3분 전 수신", "9일 전부터 수신 없음")만 보인다.
- 진동 수치는 대문에 글로 내지 않는다(2026-11-18). 문제가 있으면 색(위험 빨강·경고 주황·주의 올리브)으로만 알리고, 정확한 값은 통계 화면에서 본다.
- 연결 기준(2026-11-19 확정): 센서는 보통 1시간에 한 번 보낸다. 정상 = 마지막 수신 후 원래 간격+30초 안, 지연 = 간격×2+30초 안(한 번 빠짐), 그 뒤 미수신.
  - 원래 간격(2026-11-24): 실제 수신 간격 중앙값과 설정 주기(SENSING_PERIOD) 중 **긴 값**, 최소 60초. 예전에는 실제 간격만 써서, 옛 데이터를 몰아 재송신하면 간격이 2~3초로 잡혀 받은 지 30여 초 만에 '미수신'이 됐다. 초음파는 측정 한 번에 패킷 3~4개를 1초 간격으로 보내므로 앞 패킷과 2초 안이면 같은 측정으로 센다.
- 배터리(batteryRmin, 0~10): 목록과 카드에 막대와 숫자. 3 이하면 빨강, 아이콘(평면도·목록·카드)에 빨간 '!' 표시. 상태 색과는 따로다.
  - **2026-11-25부터 표시는 10으로 고정**이다. 지금 센서는 batteryRmin을 늘 0으로 보내(하드웨어 팀에 전달, 펌웨어 반영 전) 모두 '부족'으로 보였기 때문이다. 저장(CSV·DB)은 받은 값 0 그대로다. 시연 때 티가 나지 않도록 화면(툴팁 포함)과 `/api/site/status`에는 고정 여부를 보이지 않는다(받은 값은 API `battery`, DB `device.last_battery`로만 확인). 센서가 실제 값을 보내기 시작하면 `web_db/src/site_status.py`의 `BATTERY_DISPLAY_FIXED = 10.0`을 `None`으로 바꾼다(그 뒤 3 이하 '부족' 판정이 다시 동작).
- 오른쪽 목록 카드의 '최근 알림' 탭: 상태가 바뀐 기록(예: 11-19 06:57 BLOP 경고 → 미수신). 확인 안 한 위험·미수신·경고·지연 수가 탭에 빨간 숫자로 뜬다. 주의로 바뀐 기록은 목록에는 남지만 숫자에는 세지 않는다(1.4 근처에서 매시간 오르내리면 알림이 쌓이므로). 정상 ↔ 양호는 이름만 바뀐 것이라 기록하지 않는다. 2026-11-23 전 기록의 '경보'(한계 80%)는 지금 '경고'로 보인다. 누르면 그 센서 카드.
- 아이콘이나 목록을 누르면 정보 카드: 맨 위에 센서 사진(설정 '장치' 표에서 MAC마다 올린 것, 있을 때만. 누르면 원본을 새 탭으로), 상태와 수신 정보, 마지막 수신, 배터리. 상태 옆에 지속 시간('위험 · 3시간째'), 위험·경고·주의면 '진동 위험 · 위험 기준 4.5 mm/s 이상' / '진동 경고 · 2.8 mm/s 이상' / '진동 주의 · 1.4 mm/s 이상'(그 MAC의 경계값)과 '통계에서 확인 →' 링크(수치 없음. 누르면 통계 화면이 그 줄로 스크롤해 약 5초 강조한다. MAC은 주소에 남기지 않고 sessionStorage로 한 번만 넘긴다), 아래에 이 센서의 최근 변화 3개. MAC·원래 간격·설정은 '자세히'를 펼친다.
- 정보 카드의 **'자세히 보기 →'**는 센서 데이터 분석(`/studio`)으로 가서 그 센서 종류·MAC을 고르고 조회까지 자동으로 한다(sessionStorage로 한 번만 넘김, 주소에 MAC 안 남김). 조회는 분석 화면 기본값 **최근 50개**다(MEMS는 X/Y/Z가 다 있는 세트 50개, PIEZO·초음파는 패킷 50개). 더 보려면 '개수'(최대 200)나 '기간'으로 다시 조회한다. '통계 보기'는 통계 화면에서 그 줄을 강조한다.
- 오른쪽 센서 목록은 위쪽 ☰ 버튼이나 목록의 » 버튼으로 숨긴다. 숨기면 평면도가 넓어지고, 상태는 브라우저에 기억한다.
- 평면도가 여러 장이면 탭으로 고르고, 탭에 그 평면도의 위험·미수신·경고·지연 수 배지가 붙는다. 한 장뿐이면 탭은 숨긴다. 다른 평면도의 센서를 목록에서 누르면 그 탭으로 넘어간다.
- 범례 옆 'ⓘ 판정 기준'에 마우스를 올리면 기준이 보인다(긴 설명문은 화면에서 뺐다).
- 평면도와 배치는 여기서 바꾸지 않는다. ⚙ 버튼이 설정 '평면도 배치' 탭(`/settings#plan`)으로 간다.
- 평면도 확대·이동: 마우스 휠로 확대·축소(마우스 위치 중심, 100~600%), 확대한 상태에서 빈 곳을 끌면 이동, 오른쪽 위 + − ⤢(전체 보기) 버튼. 아이콘과 이름은 확대해도 같은 크기다. 설정 '평면도 배치'에서도 같다(확대해서 정밀하게 놓을 수 있다).
- 목록 위 검색칸: 이름이나 MAC 일부로 거른다(대소문자·공백 무시). 요약 칩 거르기와 함께 쓴다. 설정 '평면도 배치' 목록에도 있다.
- 15초마다 `/api/site/status`를 읽는다. 브라우저 탭이 안 보이면 멈춘다.

### 센서 수신 모니터 `/receiver`

연결(2026-11-19): 수신 연결은 센서 수신 모니터에서만 한다. '연결'하면 서버가 주소·Topic·구독 QoS(0/1/2, 기본 1, 2026-11-20)·CSV 체크를 `app_setting`의 `mqtt`에 기억하고, '연결 해제'를 누르기 전까지는 서버가 다시 켜져도(컨테이너 재시작·재부팅·새 이미지) 같은 값으로 다시 연결한다. 설정 화면의 '수신 MQTT' 칸은 없앴다(2026-11-19). 연결 중이면 Broker·Port·Topic·QoS·CSV 저장 칸에 **서버가 실제로 붙은 값**을 채우고 잠근다(회색). 상태 표시는 `CONNECTED 주소:포트 | 패킷 수 | CSV`, 아래 줄에 어디서 연결됐는지(이 화면에서 연결 / 서버 재시작 후 자동으로 다시 연결). 끊겨 있으면 칸이 풀리고 마지막 연결 값으로 채운다. '연결 해제'는 확인을 받는다(끊는 동안 저장되지 않음).

예전에는 `/` 주소였다. 대문이 생기면서 `/receiver`로 옮겼다.

살아 있는 수신과 센서 명령이다.

- 브로커에 연결하고 `V/#`, `D/#`와 설정 토픽 `S/#`를 구독한다.
- 들어온 파형을 RAW, FFT로 바로 본다. 이 그래프용 계산은 저장 통계와 별개다.
- CSV와 `packet` 테이블에 원본을 남긴다.
- 센서 설정을 `S/{MAC}`에 QoS 1, retain으로 보낸다(수신기 V057과 같음, 2026-11-20). 본문은 JSON만(끝 CR LF 없음), CR 포함 1024바이트 이하. 센서 타입 0~4, 주기(0 이상의 정수), Fs+N, G Range, PIEZO 게인이 JSON에 들어간다.
- **Fs + N 직접 입력**(2026-11-24, 관리자·개발자 시험용): Fs + N 목록 아래 '직접 입력' 체크를 켜면 목록이 꺼지고 Fs(Hz)·N 두 칸이 열린다(처음엔 목록에서 고른 값으로 채움, 새로고침하면 다시 목록). START·설정 적용·STOP(normal 복귀 설정)에 쓰인다. 서버(`monitor_service.custom_profile`)가 보내기 전에 검사하고 틀리면 아무것도 보내지 않는다.
  - MEMS Fs: 센서가 레지스터 코드로 받으므로 25·50·100·200·400·800·1600·3200 Hz만. PIEZO Fs: 1~102400 Hz 정수. N: 16~65536 정수(오타 방지 범위).
  - 로그인이 없어 실제 권한 제한은 아니다. 체크를 켜야만 칸이 열리게 해 실수로 바꾸는 것만 막는다.
- START·설정 적용은 수신기 V063과 같다(2026-11-23): **START는 센서 타입 칸과 상관없이 collection(PIEZO 3 / MEMS 4)** 으로 보내고 칸도 3/4로 바꾼다. **설정 적용은 고른 값 그대로**이고, 0을 고르면 아래 STOP과 같은 3단계를 밟는다.
- STOP은 3단계다: STOP(`SENSORTYPE 0`) → retain 삭제(빈 메시지) → normal 설정(PIEZO 1 / MEMS 2 + 지금 칸 값). 단계마다 PUBACK을 기다리고(최대 10초), 보내는 동안 명령 버튼이 잠긴다. 끝나면 센서 타입 칸이 normal로 돌아간다. 브로커에는 normal 설정이 남는다.
- 현재 설정 조회는 연결 줄의 QoS로 보낸다.
- 보낸 JSON은 `sensor_config`에 그 MAC 기준으로 남긴다(STOP은 마지막 normal 설정, action `STOP → normal`). 구독 중 `S/{MAC}`로 들어온 설정(브로커 retain, 데스크톱 수신기가 보낸 것 포함)도 내용이 바뀌었을 때 `retain 수신`으로 남긴다. 현재 설정 조회(`CONFIG ?`) 요청은 저장하지 않는다.
- MAC에 표시 이름을 붙여 `device`에 저장한다. 목록에 없는 MAC도 직접 입력하면 설정 적용과 이름 저장을 할 수 있다. 패킷이 아직 없어도 이름과 설정 JSON은 남는다.
- 이름과 SRSS 한계를 장치 전체로 고치는 화면은 설정 `/settings`다.
- 그래프 x축은 시간 ms, 주파수 kHz다(수신기 V063, 분석 화면과 같음). 서버 값은 s·Hz 그대로이고 화면 눈금만 바꾼다. FFT X 로그면 Hz. 범례는 오른쪽 위.
- 그래프 설정 '실시간 Welch PSD'(수신기 V063): PSD ON이면 아래 그래프가 FFT 대신 PSD다. 구간 N(8192~128, 기본 512, 패킷보다 크면 패킷 전체), Overlap %(기본 50), 평균 목표(기본 30). FFT측 필터·Window, MEMS g/LSB·감도·주파수 보정을 그대로 쓰고, MEMS FFT 단위가 mm/s RMS면 속도 PSD, 아니면 가속도 PSD다. PSD일 때 gN·SRSS·한계 가로선은 그리지 않는다. 그래프 아래 'PSD 결과'에 XYZ 합성 SRSS·한계 판정, 경고(단위 불일치, 평균 목표 미달/충족), 연산 단계 ①~⑥. 계산은 분석 화면과 같은 `graph_psd.packet_psd`(지금 패킷 하나). 수신기의 '연산 결과 CSV 자동 저장'은 아직 넣지 않았다(DB 저장 방식 논의 중).
- 축 고정은 그래프(RAW/FFT)마다 따로 지킨다. 새 패킷이 와도 고정한 축은 그대로다(2026-11-23 수정: 예전에는 대상 칸이 가리키는 그래프의 체크로 두 그래프를 함께 풀었다).
- RAW/FFT 그래프에서 곡선을 클릭하면 커서가 고정된다(2026-11-20, V057 클릭 커서). 새 패킷이 와도 같은 선·같은 X의 지금 Y를 보여 준다. 빈 곳 클릭이나 우클릭 '커서 해제'로 푼다. 두 분석 화면과 속도 RMS 시간 이력 창도 같다.

### 설정 `/settings`

탭 네 개다. 주소 끝 `#devices`, `#display`, `#plan`, `#stats`로 바로 열린다.

**장치 · 수신** (`#devices`)

- 이름·위치·진동 구간·사진만 정하고 '저장'으로 저장한다. 화면에 보일지 말지는 아래 '장치 표시' 탭(2026-11-25에 이 표 맨 앞 '표시' 칸을 옮김).

- 수신 MQTT 칸은 없다. 센서 수신 모니터에서 연결한다(위 '센서 수신 모니터' 참고).
- 이름은 `device.display_name`이다. 수신 기록이 있는 MAC은 이름만 지우고, 기록이 없는 MAC은 목록에서도 뺀다.
- **위치**(2026-11-24): 이름 옆 '위치' 칸(설치 장소, 최대 100자) = `device.location`. '저장'이 이름과 함께 보낸다(`POST /api/db/device-name`의 `location`). '추가' 줄에도 위치 칸이 있다. 통계 화면에서 이름 아래에 보인다. 수신 모니터의 이름 저장은 위치를 보내지 않으므로 위치는 그대로 남는다.
- **진동 구간**(2026-11-23): 표의 세 칸 = 양호 상한 · 주의 상한 · 위험 기준(mm/s RMS). `srss_limit`에 저장한다(`POST /api/db/zones`). 위험 기준은 예전 SRSS 한계 칸이라 그래프의 SRSS 한계선도 같은 값이다. 줄이 없으면 4.5.
  - 양호·주의 상한을 둘 다 비우면 자동: 위험 기준 × 1.4/4.5, × 2.8/4.5(ISO 비율). 4.5면 1.4/2.8, 15면 4.67/9.33. 칸 안 흐린 글자가 자동값이다.
  - 0 < 양호 상한 < 주의 상한 < 위험 기준이어야 저장된다. 한쪽만 넣으면 저장하지 않는다.
  - 분석 화면에서 SRSS 한계를 바꿔 저장한 양호·주의 상한이 새 한계 이상이 되면, 그 둘은 자동으로 되돌린다.
  - '추가'는 위험 기준만 받고 양호·주의 상한은 자동이다.
- '사진' 칸: MAC마다 사진 한 장을 올리기·바꾸기·삭제한다. PNG·JPG·WEBP, 15MB 이하(SVG는 안 받는다). 브라우저가 올리기 전에 긴 변 1600px JPEG로 줄인다. 파일은 DB가 아니라 `site_files/sensor_photos/{MAC}.jpg`(Docker는 `/data/site_files/sensor_photos/`)에 둔다. 서버는 파일 앞부분으로 진짜 이미지인지 확인한다. API: `GET/POST/DELETE /api/site/sensors/{mac}/photo`.

**장치 표시** (`#display`, 2026-11-25)

- 화면에 무엇을 보일지만 정한다. 체크는 **누르는 즉시 저장**(장치 · 수신 탭의 '저장' 버튼과 따로). 끄더라도 수신 저장·매시 통계 계산·수신 판정은 그대로다.
- 줄: 이름 · MAC · 위치 · **화면 표시**(센서 전체, `device.visible`, `POST /api/db/device-visible`) · **PIEZO · MEMS · 초음파**(종류별, `device.kind_view`, `POST /api/db/device-kind`) · 지금(보임 / 숨김 / 숨김(모든 종류) / 이름 없음) · 마지막 수신.
- 이름 있는 센서가 위(이름순), 이름 없는 MAC은 아래. 화면에 안 나오는 줄은 흐리게.
- 이름이 없으면 '화면 표시' 칸이 꺼져 있다(장치 · 수신 탭에서 이름을 붙이면 켜짐). 종류를 모두 끄면 센서째 숨김.

**평면도 배치** (`#plan`, 관리용)

대문에서 실수로 배치를 바꾸지 않게 편집은 여기로 옮겼다(2026-11-18). `static/site.js`가 편집 모드(`data-site-mode="edit"`)로 돈다.

- 평면도 추가(PNG, JPG, WEBP, SVG, 15MB 이하, 이름을 묻는다), 지금 평면도의 이미지 교체·이름 바꾸기·탭 순서(◀ ▶)·삭제. 이것들은 바로 서버에 반영된다.
- 평면도 한 장에는 센서를 여러 개 놓는다. 센서 하나는 평면도 한 장에만 놓인다(다른 평면도에 놓으면 그쪽으로 옮겨진다).
- 오른쪽 목록(평면도 없음 / 이 평면도 / 전체)의 센서를 평면도로 끌어 놓고, 아이콘을 끌어 옮기고, ×로 뺀다. 위치는 '배치 저장'을 눌러야 남고, '되돌리기'는 마지막 저장 상태로 돌린다.

**통계 데이터** (`#stats`, 관리용)

- **통계 계산 기준**(2026-11-23, `static/stat-profile.js`): 매시간 통계·센서 현황 경보가 쓰는 기준을 DB에 버전으로 둔다.
  - 칸: 환산(1 LSB당 g, MEMS 주파수·감도 보정 켬/끔과 계수), 필터(HPF·LPF 켬/끔·Hz·차수, Notch 켬/끔·Hz·폭), Welch(Window, Kaiser β, 구간 N, Overlap, 평균 목표). 첫 버전은 그래프 설정 파일 값 + HPF 10Hz·LPF 1000Hz.
  - '저장하고 다시 계산': 새 버전으로 저장하고 그 기준으로 packet 전체를 다시 계산한다(백그라운드, 진행 막대). 끝나야 지금 버전이 바뀌고, 그 전까지 통계 화면·경보는 이전 통계를 보인다. 재계산 중에는 다시 저장할 수 없다(409).
  - '지금 기준으로 다시 계산', '그래프 설정 파일 값 가져오기'(환산 칸만 JSON 파일 값으로), '기본값으로 채우기', 'JSON 내보내기·가져오기'(통계 기준 파일 또는 데스크톱의 `mems_lsb_scale.json`·`mems_frequency_sensitivity.json`도 받는다. 칸만 채우고 저장은 따로).
  - '기준 버전 기록': 버전·저장 시각·요약·메모, '칸에 불러오기'로 옛 버전을 다시 저장할 수 있다.
  - 그래프·분석 화면의 서랍 설정과는 따로다.
- 'CSV 데이터 가져오기'(2026-11-24, 전에는 'CSV로 시간별 통계 다시 만들기'): `data_csv_web`(Docker는 `/data/data_csv_web`) 아래 모든 수신 CSV(MEMS X/Y/Z, PIEZO, 초음파)를 DB `packet`에 넣는다. 이전 웹(SQLite 없음) 때 CSV만 쌓인 운영 서버용이다. 통계는 만들지 않으니 끝나면 '지금 기준으로 다시 계산'을 누른다. 가져온 기간은 센서 데이터 분석(DB) 화면에서도 열린다.
  - 안내 줄: CSV 폴더, 찾은 CSV(파일 수·폴더 수·MB), DB 패킷(실시간 수신 / CSV에서 가져옴).
  - 이미 DB에 있는 패킷(같은 MAC·축·수신 시각)은 건너뛰어 여러 번 눌러도 두 번 들어가지 않는다. 수신 중에 눌러도 된다(수신 저장은 길어야 묶음 하나 넣는 시간, 수백 ms 이하만 기다림).
  - 확인을 받고 시작한다. 진행 막대(읽은 CSV 양 / 전체)와 결과(읽은 줄·종류별 수, 넣음, 이미 있어 건너뜀, 읽지 못한 줄, CSV 기간, 걸린 시간)를 보여 준다. 결과 글자에 마우스를 올리면 수신 저장이 기다린 최대 시간과 읽지 못한 줄 예가 보인다.
  - 가져오는 동안 '다시 계산'·'저장하고 다시 계산'은 막힌다(409). 자세한 규칙은 `docs/web_db-구성과-데이터흐름.md` 'CSV 데이터 가져오기'.

### 센서 데이터 분석 `/studio`

수신으로 쌓인 DB 패킷만 연다. 파일 선택은 없다.

- MAC을 고르고, 최근 N세트 또는 시작~끝 기간으로 연다. 한 번에 최대 200세트다.
- 축 고정('X축 고정'·'Y축 고정'·'축 적용/고정')은 이전/다음 패킷으로 넘어가도 유지된다(2026-11-23 수정: 새 패킷을 그릴 때 확대 초기화가 고정 범위까지 지웠다). 데이터 분석 CSV 화면도 같다.
- 시간 이력 버튼은 지금 센서에 맞춰 바뀐다(2026-11-25). MEMS 'X/Y/Z 속도 RMS 시간 이력', PIEZO **'PIEZO 속도 RMS 시간 이력'**(패킷마다 PSD로 Vrms 한 선, 표는 패킷·packet_no·수신 시각·Vrms. 서랍 환산 값이라 통계 값과 다를 수 있어 한계선·축별 허용치·분석 데이터 저장은 없음, `graph_psd.piezo_velocity_history`), 초음파는 버튼 없음.
  서랍의 FFT HPF가 꺼져 있으면 창 안내 줄에 '통계(HPF 10 Hz·LPF 1000 Hz)와 다를 수 있음'을 붙인다. 속도는 가속도÷(2πf)라 저주파가 값을 크게 키운다(PIEZO 같은 패킷: HPF 끔 283~2,517 mm/s, 통계 기준 68~311 mm/s).
- 초음파를 고르면 서랍의 FFT·PSD·시간 이력·FFT 검증 칸을 숨긴다(2026-11-25). 초음파는 320점 스펙트럼만 있어 서버가 그 설정을 쓰지 않는다. 남는 것은 MAC 조회와 스펙트럼 그래프다.
- 서랍의 'X/Y/Z 속도 RMS 시간 이력' 창(발생기 v073): 축별 허용치(X/Y/Z 한계값 + 표시 체크, 화면 전용, SRSS 한계와 따로, 브라우저에 기억), 점 근처 툴팁(세트·수신 시각·X/Y/Z·SRSS·한계), **'분석 데이터 저장 (CSV·ZIP)'**: 지금 범위·설정으로 `acceleration_time_history.csv`, `averaged_acceleration_psd.csv`, `averaged_velocity_psd.csv`, `velocity_rms_history.csv`, `analysis_settings.json`을 ZIP 하나로 내려받는다(`POST /api/generator/velocity-export`, `src/analysis_export.py`). 값은 시간 이력 표와 같다.
- 그래프 아래 초록 패킷 정보 줄은 한 줄이다: 종류, 번호(1 / 50), **수신 시각**(ADXL은 X/Y/Z 세트 시작 시각, 초까지), 축별 RMS, SRSS. 화면보다 길면 줄바꿈 대신 가로로 민다. CSV를 연 데이터 분석 CSV 화면도 CSV에 received_at이 있으면 같은 시각이 보인다. (2026-11-23 보완: PIEZO·초음파 CSV는 시각이 비어 보였다. `load_file.load_piezo_csv`·`load_ultrasonic_csv`가 CSV `received_at`·`packet_no`를 ADXL처럼 `_received_at`·`_packet_no` 메타로 두게 했다. `_` 키는 송신 때 `replay._publish`가 빼므로 MQTT payload는 그대로다. JSON/TXT 입력은 시각 필드가 없어 빈칸이다.)
- 'FFT 평균 (Linear Averaging)': 발생기 v073의 Linear Averaging과 같다. 평균 개수만큼 패킷 FFT를 주파수 칸별로 더해 M으로 나누고, 계산식 칸에 식과 축별 M이 보인다. 끝 번호 근처에서는 앞쪽 패킷으로 개수를 채우고('전체' = 파일 전체), v073과 다른 웹 보완이다. 데이터 분석 CSV 화면도 같다.
- 고정 커서 값 상자와 툴팁: Y는 소수점 4자리, X는 반올림 없이 끝자리까지(예: 0.012890625 kHz). 값 상자는 축 이름 없이 단위만 붙는다.
- RAW·FFT·PSD 그래프 툴팁 Y값은 소수점 4자리(2026-11-23, Chart.js 기본 3자리에서 늘림), X값은 끝자리까지. 0.0001 미만·1e6 이상은 지수로 보인다. 데이터 분석 CSV 화면도 같다. 자세히는 `docs/웹-기능상세.md` '그래프 조작'.
- ADXL은 X/Y/Z가 갖춰진 `set_no`만 연다. 기간을 잘라도 세트가 쪼개지지 않는다.
- 그래프에서 PIEZO, MEMS, 초음파를 고르면 그 센서의 설정과 전송 주기만 보인다.
- 전송 체크와 Topic 입력칸은 보이지 않는다. 화면의 숨은 Topic 칸이 PIEZO·MEMS `V/{mac}`, 초음파 `D/{mac}`을 보낸다(서버 기본값과 같다).
- 전송 시작은 지금 열어 둔 DB 패킷을 고른 위치부터 브로커로 반복 송신한다.

### 데이터 분석 CSV `/generator`

두 분석 화면(이 화면과 센서 데이터 분석)은 그래프가 남는 높이를 모두 쓴다. 위 조작 줄은 낮게 둔다(2026-11-18): 라벨은 입력칸 왼쪽, 패킷 이동과 축 조작은 한 줄(좁으면 줄바꿈), 축 min/max는 칸 안 글자, 그래프 카드 제목(RAW/FFT)은 작게.

화면 배치는 센서 데이터 분석과 같다. 데이터만 파일·CSV다. SQLite는 읽지 않는다. 외부 CSV를 열어 자세히 보고, 그 파일을 MQTT로 다시 보낸다.

### 옛 통계 `/dashboard-old` (2026-11-25까지 메뉴 '통계', 지금은 비교용·메뉴에 없음)

아래는 옛 화면 설명이다. 계산·기간·최신화 규칙(아래 줄 중 화면 모양이 아닌 것)은 지금 통계 화면도 같다.

`measurement`의 지금 기준 버전 값만 그린다. 페이지를 열 때 한 번 읽고, 반복 조회는 하지 않는다. 값은 매시간 최신화 때만 바뀌기 때문이다. 열어 둔 동안 스케줄러가 돌았으면 페이지를 다시 열면 반영된다. 위 안내 줄에 계산 기준 요약(예: `계산 기준 v1: HPF 10Hz · LPF 1000Hz · 보정 주파수·감도 · …`)이 보인다.

- **PIEZO 줄**(2026-11-23): PIEZO도 한 시간 한 줄 통계가 있다. 한 축이라 막대는 'PIEZO Vrms'(그 축 속도 RMS, mm/s)이고 MAC 옆에 'PIEZO'가 붙는다. 2026-11-24부터 MEMS와 같이 설정 > 장치의 진동 구간(양호·주의 상한, 위험 기준)으로 막대 색·구간선(점선 2, 굵은 선 1)·'양호/주의/경고/위험' 글자를 보인다. 값이 MEMS보다 수십 배 클 수 있어 막대 눈금은 그 MAC의 값과 위험 기준 중 큰 값 기준이다(MEMS 공통 눈금에 넣지 않음). 2026-11-25부터 센서 현황 판정에도 같은 기준으로 들어간다(`site_status.JUDGED_KINDS`). 같은 MAC이 SENSORTYPE을 바꿔 PIEZO·MEMS를 둘 다 보낸 적이 있으면 두 줄로 따로 보인다.
- 한 줄이 MAC 하나다(위 PIEZO 예외). SRSS 막대·RMS 숫자는 고른 기간(위 기간 버튼: 24시간 기본·7일·30일·전체, 2026-11-24)의 시간 줄을 세트 수로 가중한 평균이고, PEAK 숫자는 그 기간의 최댓값이다. 작은 그래프도 그 기간의 RMS·PEAK 변화다(24시간은 한 시간 한 점 'MM-DD HH시', 7일·30일·전체는 하루 한 점 'MM-DD'(7일 = 오늘 포함 7일 → 7점): 하루 RMS는 세트 수 가중 평균, PEAK는 그날 최대).
  - 기간은 '지금'에서 거슬러 센다(24시간 = 지금 시각의 정시 − 23시간부터). 고른 기간은 브라우저(localStorage `dashboard-period`)에 기억한다. 전에는 막대·숫자가 전체 기간, 그래프만 최근 7일이라 기준이 달랐다.
  - 통계 줄은 있는데 그 기간에 없으면 '이 기간 통계 없음', 통계 줄이 하나도 없으면 '통계 전'.
  - '최근 MM-DD HH:MM 값'은 기간과 상관없이 가장 늦은 시간 줄이다(센서 현황 경보와 같은 값).
- **이름이 제목**(2026-11-24): 왼쪽 칸 맨 위에 표시 이름을 크게, 그 아래 설치 위치(설정 > 장치 '위치', 있을 때만), MAC·기간 세트 수는 작게 보인다. 이름이 없으면 MAC이 제목이다. PIEZO 줄은 이름 옆에 'PIEZO' 꼬리표.
- **초음파 센서는 보이지 않는다**(2026-11-24): 아직 이상으로 판정할 기준이 없어 통계를 계산하지 않는다. 통계 줄이 없고 마지막 수신 종류(`device.last_sensor`)가 ULTRASONIC인 MAC은 목록에서 뺀다.
- 막대와 '최근 MM-DD HH:MM 값'의 색·글씨는 센서 현황과 같은 네 구간(양호 초록·주의 올리브·경고 주황·위험 빨강, 그 MAC의 경계)이다. 막대 안 점선 두 개가 양호·주의 상한, 굵은 선이 위험 기준이다. 통계가 없는 MAC은 '-'.
- 센서 현황 카드의 '통계에서 확인'·'통계 보기'로 오면 그 MAC 줄로 스크롤하고 약 5초 빨간 테두리로 강조한 뒤 풀린다. MAC은 주소(GET)에 남기지 않고 sessionStorage('dashboard-focus')로 넘겨 한 번 읽고 지운다(POST로 열면 새로고침 때 '양식 다시 제출' 경고가 떠서 쓰지 않음). 새로고침하면 다시 강조되지 않는다.
- 최신화 버튼은 없다(2026-11-18). 사람마다 다른 시각에 최신화하면 보는 값의 기준이 달라지기 때문이다. 화면 위에 `마지막 계산 YYYY-MM-DD HH:MM`을 보여 준다.
- 서버가 켜져 있는 동안 1분마다 시각을 보고, 마지막 계산의 '시'가 지금보다 이전이면 최신화한다(매시 정각 뒤 1분 안). 이 스케줄러는 프로세스에 하나뿐이다.
- 통계 작업은 한 번에 하나만 돈다. 스케줄러와 재계산이 겹치면 뒤의 것은 앞의 것이 끝날 때까지 기다린다. CSV 가져오기 중에는 재계산을 시작할 수 없다. 같은 세트가 두 번 들어가지 않는다.
- 계산하는 동안 SQLite 잠금은 300줄 읽기·쓰기 순간만 잡는다. 수신 저장이 기다린 시간은 최대 수십 ms다(`docs/web_db-DB명세서.md`).

### 통계 `/dashboard` (2026-11-24 `/dashboard2`로 만들고, 2026-11-25부터 메뉴 '통계'가 이 화면)

옛 통계 화면과 같은 값(`/api/db/dashboard`)을 보기 좋게 정리한 화면. 옛 `/dashboard2` 주소는 없앴고(404), 옛 화면은 `/dashboard-old`(메뉴에 없음, 비교용)에 남겼다. 센서 현황 카드의 '통계에서 확인 →'은 이 화면에서 그 센서 카드로 옮겨 약 5초 강조한다(sessionStorage `dashboard-focus`, 한 번만). 기간 버튼(24시간 기본·7일·30일·전체)은 localStorage `dashboard2-period`에 기억한다. 흰색·회색·검정 테마 모두 맞춘다.

- 위: 제목, 마지막 계산 시각·계산 기준, 기간 버튼.
- **구간별 센서 수**: 센서 수, 양호·주의·경고·위험, 이 기간 통계 없음(기간 평균 속도 기준. 센서 현황 경보는 '최근 한 시간' 값이라 다를 수 있다).
- **속도 RMS 기간 평균 세로 막대**(높은 순, 밑에서 위로. 11-24 가로 → 세로): MEMS(세 축 SRSS)와 PIEZO(한 축 Vrms, 환산 확인 전이라 따로 눈금)를 나눈다. 칸마다 위에 값, 아래에 이름과 **전체 MAC·위치**, 막대 색은 구간, 점선은 양호·주의 상한, 빨간 가로선은 위험 기준. 칸을 누르면 아래 그 센서 카드로 가서 잠시 강조한다. 통계가 한 번도 없는 센서는 막대에서 뺀다.
- **센서 카드**: 이름·MEMS/PIEZO·구간 표시·'+ 자세히' / 전체 MAC·위치·기간 세트 수·최근 한 시간 값·위험 기준 / 속도 RMS(mm/s)·RMS(g)·PEAK(g) 작은 그래프(속도 그래프는 값이 위험 기준의 60% 이상이면 위험 기준 점선도).
- 그래프 점: 24시간은 한 시간 한 점, 7일·30일·전체는 하루 한 점(7일 = 7점).
- 이름이나 **'+ 자세히'**를 누르면 그 센서 통계 창(모달)이 속도 RMS부터 뜬다. 그 MAC만 다시 읽는다(`?mac=&bucket=`).
  - 요약 칸: 속도 기간 평균(구간)·축별 속도 평균·RMS 평균·PEAK 최대·세트 수(첫~끝 시각)·최근 한 시간.
  - 지표(속도 RMS / RMS / PEAK), 기간, **시간별 / 일별** 버튼(기본: 24시간은 시간별, 나머지는 일별). 속도에는 X/Y/Z 축, 시간(그날) 안 최대 SRSS, 양호·주의 상한·위험 기준 점선. 좌우로 끌면 확대, '확대 원래대로'.
  - 아래 표: 시간(또는 일) 줄을 최근 것부터. 닫기: ×, 창 바깥, Esc.

## 테이블

| 테이블          | 역할                                            |
| --------------- | ----------------------------------------------- |
| `device`        | MAC, 표시 이름, 마지막 수신 정보                |
| `packet`        | 수신 원본. 통계 계산 전                         |
| `sensor_config` | 그 MAC에 마지막으로 retain 전송한 설정 JSON     |
| `measurement`   | MAC마다 한 시간 한 줄(SRSS mm/s 평균·최대, X/Y/Z 속도 RMS, RMS, PEAK, 세트 수, 기준 버전). 전체 값은 화면에서 가중 평균 |
| `stat_profile`  | 통계 계산 기준 버전(g/LSB, MEMS 보정, 필터, Window, Welch). 지금 버전은 `app_setting` 'stat_profile_active' |
| `stat_cursor`   | MAC마다 통계가 이미 읽은 마지막 packet id. 계산에 실패한 세트도 다시 읽지 않는다 |
| `stat_meta`     | 통계를 마지막으로 만든 시각                     |
| `srss_limit`    | 설정 화면의 MAC별 SRSS 한계. 없으면 4.5 mm/s RMS |

## CSV 분석과 DB 분석

데이터 출처는 화면마다 하나다.

- 데이터 분석 CSV `/generator`는 외부 파일만 연다. SQLite는 읽지 않는다.
- 센서 데이터 분석 `/studio`는 DB 패킷만 연다. 파일 선택은 없다.
- 둘 다 같은 그래프와 MQTT 재전송을 쓴다. 계산과 송신 스크립트는 `generator-draw.js`, `generator-api.js`다. DB를 고르는 스크립트는 `db.js`다.
- 센서 수신 모니터는 받아서 저장하고 명령을 보낸다. 통계는 `measurement`만 본다. 설정은 이름과 SRSS 한계만 다룬다.
