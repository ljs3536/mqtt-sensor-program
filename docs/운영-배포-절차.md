# 운영 서버 첫 배포 절차 (SQLite 새로 만들기 + CSV로 packet 채우기)

2026-11-24 작성. 이전 웹(SQLite 없음) 때 수신 CSV만 쌓여 있는 운영 서버에 `web_db`를 처음 올릴 때의 순서다.

## 한눈에

| 순서 | 어디서 | 할 일 | 결과 |
| --- | --- | --- | --- |
| 1 | 로컬 PC | 설정만 담은 DB 만들기 `python -m web_db.src.export_settings 출력폴더\sensor.sqlite` | `sensor.sqlite`(설정만) + `site_files/`(평면도·센서 사진) |
| 2 | 운영 서버 | `data_csv_web`에서 재송신·시험 폴더 빼기(아래 '주의 1') | 실측 CSV만 남음 |
| 3 | 운영 서버 | 1의 결과를 `./sensor_web_db/`에 넣고 서버 켜기(`docker compose up -d --force-recreate`) | 이름·위치·구간·평면도·통계 기준이 그대로인 빈 DB |
| 4 | 화면 | 센서 수신 모니터에서 브로커 `192.168.0.2`, 포트 `1883`으로 '연결'(CSV 저장 체크). 연결 해제를 누르기 전까지 서버·컨테이너가 다시 켜져도 자동으로 다시 붙는다. **`127.0.0.1`은 쓰지 않는다**: 컨테이너 안의 127.0.0.1은 웹 컨테이너 자신이라 브로커에 닿지 않는다(서버 PC 자신은 `host.docker.internal`) | 실시간 수신 시작 |
| 5 | 화면 | 설정 > 통계 데이터 > 'CSV 데이터 가져오기' | CSV가 `packet`(source='csv')으로 |
| 6 | 화면 | 같은 탭 '지금 기준으로 다시 계산' | 모든 기간 시간별 통계 |
| 7 | 화면 | 확인(아래 '확인할 것') | |

설정을 옮기지 않고 빈 DB로 시작해도 동작은 같다. 다만 **이름이 없는 센서는 센서 현황·통계·분석에 보이지 않으므로**(2026-11-24 규칙) 설정 > 장치에서 이름을 다시 붙여야 한다.

## 1. 설정만 담은 DB 만들기 (`web_db/src/export_settings.py`)

```
.venv\Scripts\python.exe -m web_db.src.export_settings D:\deploy\sensor_web_db\sensor.sqlite
.venv\Scripts\python.exe -m web_db.src.export_settings D:\deploy\sensor_web_db\sensor.sqlite --from web_db\sensor.sqlite --with-mqtt
```

- 원본(기본은 서버가 쓰는 DB)은 **읽기만** 한다. 로컬 서버가 켜져 있어도 된다.
- 새 파일 경로에 파일이 이미 있으면 멈춘다(덮어쓰지 않음).
- 스키마는 서버가 켜질 때와 같은 코드(`Store._migrate`)로 만든다. 그래서 운영 서버가 켜질 때 바꿀 것이 없다.

| 옮기는 것 | 비고 |
| --- | --- |
| `device` 표시 이름·위치·표시(visible)·처음 본 시각 | 사용자 값이 있는 MAC만(이름·위치가 있거나, 표시를 껐거나, 구간·평면도 위치를 정한 MAC). 마지막 수신(`last_*`)은 비운다 |
| `srss_limit` 위험 기준·양호/주의 상한 | 전부 |
| `stat_profile` + `app_setting.stat_profile_active` | 같은 id. 운영 서버의 MEMS 보정 JSON이 달라도 통계 기준이 로컬과 같다 |
| `floor_plan`·`sensor_placement` + `site_files/` | 평면도 이미지, 센서 위치, 센서 사진 |
| `app_setting.mqtt` | `--with-mqtt`일 때만. 로컬 주소(127.0.0.1)가 운영에 가지 않게 기본은 뺀다 |
| `sensor_config` | `--with-sensor-config`일 때만. 운영 브로커의 retain(`S/MAC`)이 구독하는 순간 다시 채운다 |

옮기지 않는 것: `packet`(수신 원본), `measurement`·`stat_cursor`·`stat_meta`(통계), `site_state`·`site_state_history`(상태 기록).

## 2~3. 운영 서버에 넣고 켜기

- Docker: 1의 결과(`sensor.sqlite`, `site_files/`)를 compose 파일 옆 `./sensor_web_db/`에 넣는다. **서버를 켜기 전에** 넣는다
  (켜진 뒤 바꾸면 서버가 쥔 연결과 어긋난다). 파일 주인은 컨테이너 시작 스크립트가 `./data_csv_web` 주인으로 맞춘다.
- Docker 없이: `web_db/sensor.sqlite`와 `web_db/site_files/`.
- 시간대: 이미지가 `TZ=Asia/Seoul`이다. 옛 CSV(`received_at`)도 한국 시각이라 그대로 이어진다. 시간대를 바꾸면 시간 묶음이 어긋난다.
- 켜지면: 통계 기준 v1이 이미 '지금 버전'이라 시작 재계산은 돌지 않고, 매시간 통계가 바로 돈다.

## 5. CSV 데이터 가져오기

`data_csv_web` 아래(하위 폴더 포함) 모든 `*_sensorData_hex.csv`를 읽는다. 수신 중에 눌러도 된다(잠금은 묶음마다 수십 ms).

- **중복**: 같은 MAC·종류·축·수신 시각이 이미 있으면 건너뛴다. 새 웹이 수신하면서 같은 폴더에 쓴 CSV도 다시 들어가지 않고, 여러 번 눌러도 안전하다.
- **깨진 줄**: HEX 길이가 홀수이거나 N과 맞지 않는 줄은 건너뛰고 결과에 개수를 남긴다(실시간 수신도 버리는 패킷). 로컬 실측 3,092줄 중 59줄(925874312270 MEMS가 대부분).
- 마지막 수신(`device.last_at`)은 가져온 가장 늦은 패킷으로 맞춰진다(2026-11-24 고침, 전에는 첫 묶음 시각에 멈췄다).

## 6. 다시 계산

가져오기가 끝나면 '지금 기준으로 다시 계산'. 매시간 통계도 가져온 줄을 더하지만(결과는 같다), 다시 계산 한 번이 확실하다.
로컬 측정: 4,516세트 15.6초. 한 달치(센서 12대 한 시간마다)면 1분 안팎이다. 계산 중에도 수신·화면은 그대로다.

## 주의

1. **재송신·시험 데이터가 CSV에 섞여 있으면 실측처럼 들어간다.** 웹은 받은 것을 모두 CSV로 남기므로, 옛 데이터를 재송신(데이터 분석 CSV 송신 등)하면
   같은 파형이 새 수신 시각으로 다시 기록된다. 가져오기의 중복 확인은 수신 시각 기준이라 이것을 막지 못한다.
   로컬 `data_csv_web` 141개 폴더 5,303줄 중 2,192줄이 앞 줄과 HEX가 같은 재송신이었다(11-12~11-24 시험 폴더).
   2026-11-24 로컬 DB 정리 때 지운 2,211줄과 거의 같다. 그래서 로컬에서 지금 이 버튼을 누르면 **지운 재송신 줄이 다시 들어온다**.
   운영 서버에서 재송신을 했다면 그 날짜 폴더를 `data_csv_web` 밖으로 옮긴 뒤 가져온다.
2. `packet`은 지우지 않는다. MEMS 한 패킷 HEX가 약 33 KB라, 센서 12대가 모두 MEMS로 한 시간마다 보내면 한 달에 약 0.9 GB씩 는다(3축 × 24 × 30 × 12대 ≈ 2.6만 패킷). 디스크를 본다.
3. 서버는 프로세스 하나로만 돈다(`--workers 1`). MQTT 상태·SQLite 잠금·매시간 통계가 한 프로세스 메모리에 있다.
