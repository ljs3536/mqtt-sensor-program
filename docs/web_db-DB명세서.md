# web_db DB 명세서

기준은 `http://127.0.0.1:8081` 의 `web_db/sensor.sqlite`다. 이 문서는 통계를 위해 정한 저장 계획이다. 수신 화면의 RAW, FFT는 이 테이블을 쓰지 않는다.

DB로 바꾼 이유는 CSV다. 패킷은 연결할 때마다 폴더에 계속 쌓이고, 통계를 만들려면 그 파일 전부를 찾아 해당하는 CSV를 모두 읽어야 했다. 원본은 `packet`에 쌓아 두고, 통계 숫자는 그 테이블만 읽어 `measurement`에 만든다.

## 역할

| 테이블 | 역할 |
| --- | --- |
| `device` | MAC 명부. 표시 이름과 마지막 수신 정보. MAC당 한 줄 |
| `packet` | 수신 원본. 디코드된 패킷마다 한 줄씩 계속 추가한다. 통계 숫자는 없다 |
| `sensor_config` | 그 MAC에 마지막으로 retain 전송한 설정 JSON. MAC당 한 줄 |
| `measurement` | 통계 결과. MAC당 한 줄. 스케줄러 또는 통계 화면 새로고침이 `packet`을 읽어 이 줄을 갈아 끼운다 |
| `stat_meta` | `measurement`를 마지막으로 만든 시각 |

`daily_stat`은 통계 경로에서 쓰지 않는다. 날짜별 평균을 보여 주는 화면도 없고, 통계 조회도 이 테이블을 읽지 않는다. 통계의 저장소는 `measurement` 한 곳이다.

`srss_limit`는 통계 계산 결과가 아니다. 설정 화면에서 저장한 MAC별 한계(mm/s RMS)이고, 막대와 그래프 기준선이 이 테이블을 읽는다. 키는 MAC을 대문자로 바꾸고 `:`와 `-`를 뺀 문자열이다. 줄이 없으면 4.5다. 예전에 사용자 홈 JSON에만 있던 값은 서버가 켜질 때 테이블에 없는 키만 한 번 옮긴다.

## packet

측정 JSON이 디코드되면 바로 한 줄 넣는다. 이 시점에는 RMS, PEAK, SRSS를 계산하지 않는다. MQTT가 끊겼다가 다시 붙어도 세션 줄은 만들지 않는다. 같은 MAC의 `device` 줄을 갱신하고 `packet`에 이어서 넣는다. `set_no`는 연결이 아니라 직전 패킷의 seq로 정한다.

ADXL은 축마다 한 줄이다. seq 상위 4비트는 축, 하위 4비트는 축을 보낼 때마다 1씩 증가한다. `10`, `21`, `32`처럼 이어지면 같은 세트다. 축이 빠져도 도착한 줄은 남긴다. 빠진 축 때문에 저장을 멈추지 않는다.

PIEZO와 초음파도 같은 테이블에 쌓인다. 통계 계산의 대상은 아니다.

지우는 주기는 없다. 통계를 만들 때 CSV를 다시 열지 않는 대신, 이 테이블이 원본이다.

## measurement

MAC당 한 줄이다. 세트가 끝날 때마다 줄을 추가하지 않는다. 표의 기본 키는 `id`이고, 한 줄을 유지하는 방법은 최신화 때 그 MAC의 ADXL 줄을 지운 뒤 하나만 넣는 것이다. `set_key`는 `ADXL|{MAC}|all`이다.

갱신 시점은 둘이다.

- 통계 화면에서 새로고침을 확인하고 최신화를 실행할 때
- 서버가 켜져 있는 동안 스케줄러가 같은 최신화를 실행할 때

둘 다 하는 일은 같다. 그 MAC의 `packet`을 읽어 완성된 ADXL X/Y/Z 세트만 고르고, 결과를 그 MAC의 `measurement` 한 줄에 덮어쓴다. 수신 콜백에서는 하지 않는다.

한 줄에 넣는 값은 그 시점까지 쌓인 완성 세트 전체의 결과다. 마지막 세트 하나가 아니다.

세트 하나의 숫자는 저장된 샘플 전체로 만든다. 그래프의 필터, Window N, 주파수 보정은 넣지 않는다. 창은 Blackman이다.

- 세트 RMS: 축마다 시간 영역 AC RMS를 구한 뒤 `sqrt(X²+Y²+Z²)`. 단위는 g
- 세트 PEAK: 세 축 샘플 중 절대값이 가장 큰 값. 단위는 g
- 세트 SRSS: 세 축 스펙트럼 전력을 합친 뒤 제곱근. 단위는 g RMS
- 세트 SRSS mm/s: 같은 스펙트럼을 `g × 9806.65 / (2πf)`로 바꾼 뒤 같은 방식으로 합친 값

MAC 한 줄에는 이렇게 모은다.

| 열 | 내용 |
| --- | --- |
| `mac` | 장치. 최신화 후 ADXL 줄은 이 값당 하나 |
| `received_at` | 넣은 세트 중 가장 늦은 수신 시각. `last_at`과 같다 |
| `rms` | 완성 세트 RMS의 평균. 단위는 g |
| `peak` | 완성 세트 PEAK의 최댓값. 단위는 g |
| `srss` | 완성 세트 SRSS(g RMS)의 평균 |
| `srss_mms` | 완성 세트 SRSS(mm/s RMS)의 평균. 통계 막대가 읽는 값 |
| `set_count` | 이번 계산에 넣은 완성 세트 수. 통계 한 줄임을 구분하는 값 |
| `first_at` | 넣은 세트 중 가장 이른 수신 시각 |
| `last_at` | 넣은 세트 중 가장 늦은 수신 시각 |
| `computed_at` | 이 줄을 쓴 시각 |
| `g_per_lsb` | 이번 계산에 쓴 눈금 |
| `sample_rate`, `sample_count` | 넣은 세트가 모두 같으면 그 값. 섞이면 비운다 |
| `set_key` | `ADXL|{MAC}|all` |
| `unit` | `g RMS` |

축이 하나라도 없는 세트, 샘플이 2개 미만인 세트, 세 축의 샘플 수나 샘플링 속도가 다른 세트는 평균에 넣지 않는다. 그 패킷 줄은 `packet`에 그대로 둔다.

완성 세트가 하나도 없으면 `measurement` 줄은 만들지 않는다. 이전에 있던 줄은 유지하지 않고 제거한다. 화면에 옛 평균이 남지 않게 하기 위해서다.

## 통계 화면이 읽는 것

통계 화면은 `measurement`만 읽는다. 페이지를 열거나 다시 그릴 때는 계산하지 않는다.

MAC 한 줄이 곧 그 장치의 전체 결과다. 막대는 `srss_mms`, 숫자는 그 줄의 RMS와 PEAK다. 세트마다 쌓인 추세는 이 모델에 없다.

분석 화면이 파형을 열 때는 `measurement`를 쓰지 않는다. `packet`에서 고른 세트의 샘플을 읽는다.

## 구현

통계 최신화는 이 명세대로 한다. 수신 중에는 `packet`만 늘리고 `measurement`는 건드리지 않는다. 새로고침 확인과 스케줄러가 MAC의 패킷을 읽어 한 줄로 덮어쓴다.
