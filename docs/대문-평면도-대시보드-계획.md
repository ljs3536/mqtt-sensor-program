# 대문(평면도) 대시보드 계획

웹의 첫 화면을 평면도 대시보드로 바꾼다. 평면도 이미지 위에 센서 아이콘을 놓고, 센서마다 연결 상태, 데이터 수신 여부, 알람(통계 SRSS가 한계를 넘었는지)을 한눈에 본다.

진행 방식: 최소안부터 차근차근 한다. 정해야 할 것이 생기면 작업을 멈추고 묻는다.

## 정한 것

| # | 항목 | 결정 |
| --- | --- | --- |
| A2 | 수신 연결 | 설정 화면에 저장한 MQTT 값으로 서버가 켜질 때 자동 연결한다 |
| A3 | 알람 값 | 최신화하지 않고, 이미 쌓인 통계(`measurement`) 값으로 판정한다. 통계 화면과 같은 값(세트 수로 가중한 SRSS 전체 평균)과 같은 기준(한계 이상 = 초과, 80% 이상 = 주의) |
| A5 | 평면도 | 여러 장(넓은 현장은 한 장에 다 못 그린다, 2026-11-18). 화면은 탭. 평면도 한 장에 센서 여러 개, 센서 하나는 평면도 한 장에만 |

## 연결 판정 (B4)

센서는 따로 생존 신호를 보내지 않는다. 그래서 "마지막으로 데이터가 들어온 시각"과 "원래 들어와야 하는 간격"을 비교한다.

간격을 아는 방법

1. 실제 수신 간격: SQLite `packet`에서 그 MAC의 최근 측정 시각 간격의 중앙값. 실제로 들어오는 간격이라 가장 정확하다. 측정이 3번 이상 있어야 쓴다.
   ADXL은 축 순서(X→Y→Z)로 한 측정을 묶는다. 처음에는 "2초 안에 붙어 온 패킷"으로 묶었는데, 실제 CSV(2026-11-06)는 축 사이가 약 5.5초라 축 간격(약 5초)을 측정 주기(약 1시간)로 잘못 보았다. 고친 뒤 이 자료의 간격은 약 3,600초로 나온다.
2. 설정 주기 `SENSING_PERIOD`: `S/{MAC}` 설정 JSON. 웹이 보낸 설정뿐 아니라, 구독할 때 브로커가 주는 retain 설정(데스크톱 수신기가 보낸 것 포함)도 받아서 `sensor_config`에 남긴다.
3. `CONFIG ?` 조회 응답: 기술적으로는 주기적으로 물어볼 수 있다. 하지만 측정 사이에 잠든 센서가 응답하는지는 펌웨어에 달려 있어 쓰지 않는다. 필요하면 펌웨어 동작을 확인한 뒤 추가한다.

임시 기준 (`web_db/src/site_status.py` 한 곳에 상수로 둔다)

| 상태 | 조건 |
| --- | --- |
| 수신 꺼짐 | 서버의 MQTT 수신이 연결되어 있지 않음(모든 센서 판정 불가) |
| 측정 중지 | 마지막 설정이 `SENSORTYPE 0`(STOP) |
| 기록 없음 | 받은 패킷이 없음 |
| 정상 | 마지막 수신 후 경과 ≤ 간격 × 2 + 30초 |
| 지연 | 경과 ≤ 간격 × 5 + 30초 |
| 끊김 | 그보다 오래됨 |
| 주기 미상 | 간격을 알 수 없음(경과 시간만 표시) |
